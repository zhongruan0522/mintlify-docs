---
title: Docker Deployment
---

This document explains how to run NookMux directly from the Docker image. Production still recommends [Docker Compose Deployment](/nookmux/installation/deployment-methods/docker-compose-installation) so you can manage Redis, logs, and data volumes in one place.

## Basic Requirements

- Docker installed.
- The default listening port is `3000`.
- You must mount `/data` to store the SQLite database and upload/cache data.

## Run with SQLite

```shell
docker run --name nookmux -d --restart always \
  -p 3000:3000 \
  -e TZ=Asia/Shanghai \
  -e SESSION_SECRET=replace_with_a_random_string \
  -e CRYPTO_SECRET=replace_with_another_random_string \
  -v /your/data/path:/data \
  ghcr.io/nookmux/nookmux:latest
```

<Card type="warning" title="Data persistence">
  Replace `/your/data/path` with a real host directory and make sure the container has read/write access. If `/data` is not mounted, data will be lost after the container is recreated.
</Card>

## Run with external MySQL

```shell
docker run --name nookmux -d --restart always \
  -p 3000:3000 \
  -e SQL_DSN="mysql://user:password@db-host:3306/nookmux" \
  -e TZ=Asia/Shanghai \
  -e SESSION_SECRET=replace_with_a_random_string \
  -e CRYPTO_SECRET=replace_with_another_random_string \
  -v /your/data/path:/data \
  ghcr.io/nookmux/nookmux:latest
```

## Run with external openGauss

Switch `SQL_DSN` to the `opengauss://` prefix to connect openGauss 7.0 (the target database must be created with `DBCOMPATIBILITY='PG'`):

```shell
docker run --name nookmux -d --restart always \
  -p 3000:3000 \
  -e SQL_DSN="opengauss://user:password@db-host:5432/nookmux" \
  -e TZ=Asia/Shanghai \
  -e SESSION_SECRET=replace_with_a_random_string \
  -e CRYPTO_SECRET=replace_with_another_random_string \
  -v /your/data/path:/data \
  ghcr.io/nookmux/nookmux:latest
```

## Run with external Dameng DM8

Switch `SQL_DSN` to the `dm://` prefix to connect Dameng DM8 (the instance must be initialized with `CASE_SENSITIVE=N`, and the account needs the `SELECT ANY DICTIONARY` privilege):

```shell
docker run --name nookmux -d --restart always \
  -p 3000:3000 \
  -e SQL_DSN="dm://user:password@db-host:5236?schema=NOOKMUX" \
  -e TZ=Asia/Shanghai \
  -e SESSION_SECRET=replace_with_a_random_string \
  -e CRYPTO_SECRET=replace_with_another_random_string \
  -v /your/data/path:/data \
  ghcr.io/nookmux/nookmux:latest
```

## Run with external KingbaseES

Switch `SQL_DSN` to the `kingbase://` prefix to connect KingbaseES in Oracle-compatible mode (the instance must not enable `enable_ci`, otherwise startup is rejected; percent-encode the password per URL rules):

```shell
docker run --name nookmux -d --restart always \
  -p 3000:3000 \
  -e SQL_DSN="kingbase://user:password@db-host:54321/nookmux?sslmode=disable" \
  -e TZ=Asia/Shanghai \
  -e SESSION_SECRET=replace_with_a_random_string \
  -e CRYPTO_SECRET=replace_with_another_random_string \
  -v /your/data/path:/data \
  ghcr.io/nookmux/nookmux:latest
```

## Optional: connect Redis

```shell
-e REDIS_CONN_STRING="redis://:password@redis-host:6379"
```

With Redis configured, cross-node caching and synchronization are enabled. For multi-node deployments, all nodes must use the same Redis instance and the same `SESSION_SECRET` / `CRYPTO_SECRET` values.

## Access the System

After deployment, visit `http://Server_IP:3000`. The first visit opens the initialization page. After completing initialization, log in with the administrator account you created.

<Card type="warning" title="Security window during first-time initialization">
  The initialization endpoint (`/api/setup`) is anonymous until initialization completes. If a fresh instance is exposed to the public internet, an external visitor could register the root administrator account before you do. Complete the first-time initialization from an internal network, or restrict access to port `3000` (in particular the `/api/setup` path) with a firewall/security group first and open it up after initialization. Once initialization is complete, the endpoint is automatically disabled: further calls to `/api/setup` are rejected.
</Card>
