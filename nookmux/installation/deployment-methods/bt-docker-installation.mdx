---
title: Baota Panel Deployment
---

This document explains how to deploy NookMux using Baota Panel's Docker features.

## Prerequisites

- Baota Panel version 9.2.0 or later.
- Docker service installed in the panel.
- The server has port `3000` or the external port you plan to map open.

## Create the Container

1. Log in to Baota Panel and open **Docker**.
2. On first entry, follow the prompts to install the Docker service.
3. Open **Image Management** and pull the image:

   ```text
   ghcr.io/nookmux/nookmux:latest
   ```

4. Open **Container List** and click create container.
5. Fill in the container settings:

| Item | Suggested Value |
| --- | --- |
| Container Name | `nookmux` |
| Image | `ghcr.io/nookmux/nookmux:latest` |
| Port Mapping | `3000:3000` |
| Directory Mapping | `/your/host/data:/data`, `/your/host/logs:/app/logs` |
| Startup Command | `--log-dir /app/logs` |
| Environment Variables | `TZ=Asia/Shanghai`, `SESSION_SECRET=...`, `CRYPTO_SECRET=...` |

<Card type="warning" title="Production security settings">
  `SESSION_SECRET` and `CRYPTO_SECRET` should be different random strings. Do not use sample values or publicly exposed strings.
</Card>

## Optional Database and Redis

SQLite is used when `SQL_DSN` is not set. The database file is stored at `/data/one-api.db`. If you use an external database or Redis, add:

```text
SQL_DSN=mysql://user:password@db-host:3306/nookmux
REDIS_CONN_STRING=redis://:password@redis-host:6379
```

PostgreSQL example:

```text
SQL_DSN=postgres://user:password@db-host:5432/nookmux
```

openGauss example (the target database must be created with `DBCOMPATIBILITY='PG'`):

```text
SQL_DSN=opengauss://user:password@db-host:5432/nookmux
```

Dameng DM8 example (the instance must be initialized with `CASE_SENSITIVE=N`, run in DM native mode (`COMPATIBLE_MODE=0`, a dm.ini parameter), the account needs the `SELECT ANY DICTIONARY` privilege, and the password is written literally — it must not contain `?` (`:` and `@` are allowed)):

```text
SQL_DSN=dm://user:password@db-host:5236?schema=NOOKMUX
```

KingbaseES example (Oracle-compatible mode; the instance must not enable `enable_ci`, otherwise startup is rejected; percent-encode the password per URL rules):

```text
SQL_DSN=kingbase://user:password@db-host:54321/nookmux?sslmode=disable
```

Production sizing notes:

- KingbaseES defaults to `max_connections=100`. The main database and the log database each run an independent connection pool with a default cap of 1000 (`SQL_MAX_OPEN_CONNS`), so lower it well below the instance session limit (for example `SQL_MAX_OPEN_CONNS=50`); otherwise new connections fail with `FATAL 53300: sorry, too many clients already` at peak load.
- Keep `sslmode=disable` in the DSN for instances without SSL: the Gokb driver defaults to `require` with no plaintext fallback.
- The Gokb driver's default path costs two round trips per parameterized statement with no statement cache; `SQL_PREPARE_STMT=true` is recommended for production workloads.

## Access the System

After the container starts, visit:

```text
http://Server_IP:3000
```

The first visit opens the initialization page. After creating the administrator account, you can log in.

## Common Issues

### Cannot Access the Interface

- Check whether the port mapping is correct.
- Confirm that the server firewall and cloud security group allow the port.
- Check the container logs to confirm the service started successfully.

### Data Loss

- Confirm `/data` is mapped correctly.
- Confirm the host directory permissions allow container read/write access.
- If the process is force-killed (e.g. host power loss, `kill -9`), at most the last few seconds of statistics deltas (used quota, request count) may be lost; balance and quota deductions are written synchronously, so negative balances cannot occur.
