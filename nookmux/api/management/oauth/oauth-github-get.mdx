---
title: GitHub OAuth Login
description: OAuth callback for GitHub login and account binding, protected by a session-bound state parameter.
api: "GET /api/oauth/github"
---

GitHub OAuth callback. NookMux registers GitHub through the unified `GET /api/oauth/{provider}` route with `provider=github`; the browser is redirected here by GitHub after authorization. The endpoint completes two different flows depending on the caller's session:

- Not logged in: finds or creates the NookMux account linked to the GitHub identity and signs the user in (the login session cookie is set on the response).
- Already logged in in the same browser session: binds the GitHub identity to the current account and returns `action: "bind"`.

Before redirecting the user to GitHub, the frontend must call [Generate OAuth State](/nookmux/api/management/oauth/oauth-state-get) in the same session; the `state` returned by that call must round-trip through GitHub back to this endpoint.

This endpoint is **Public**; no access token is required. It is protected by a stricter rate limit (CriticalRateLimit). See [Authentication](/nookmux/api/management/auth) for how management API requests are authenticated.

## Request

<RequestExample>

```bash cURL
curl --request GET \
  --url 'https://your-nookmux-domain/api/oauth/github?code=gh-oauth-code-xxxxxxxxxxxx&state=abc123def456'
```

</RequestExample>

### Path parameters

<ParamField path="provider" type="string" required>
  OAuth provider name. GitHub uses `github`. NookMux currently registers two providers: `github` and `linuxdo`.
</ParamField>

### Query parameters

<ParamField path="state" type="string" required>
  CSRF state generated by `GET /api/oauth/state` and stored in that session. Must match the value in the session cookie, otherwise the request is rejected with HTTP `403`.
</ParamField>

<ParamField path="code" type="string" required>
  Authorization code returned by GitHub. Exchanged server-side for an access token and user info.
</ParamField>

<ParamField path="error" type="string">
  Error code passed by GitHub when authorization failed. When present, the endpoint returns `success: false` without contacting GitHub.
</ParamField>

<ParamField path="error_description" type="string">
  Human-readable error description passed by GitHub. Returned verbatim in the `message` field when `error` is present.
</ParamField>

## Response

<ResponseExample>

```json 200
{
  "success": true,
  "message": "",
  "data": {
    "id": 42,
    "username": "octocat_12345678",
    "display_name": "Octocat",
    "role": 1,
    "status": 1,
    "group": "default"
  }
}
```

</ResponseExample>

### Response fields

<ResponseField name="success" type="boolean" required>
  Whether the login or bind completed.
</ResponseField>

<ResponseField name="message" type="string" required>
  Error description when `success` is `false`; for the bind flow it is `Binding successful`.
</ResponseField>

<ResponseField name="data" type="object" required>
  Payload differs by flow.

  <Expandable title="login data structure">
    <ResponseField name="id" type="integer" required>
      User id of the signed-in account.
    </ResponseField>
    <ResponseField name="username" type="string" required>
      Login username. Newly registered OAuth users get a username derived from the provider username and provider user id.
    </ResponseField>
    <ResponseField name="display_name" type="string" required>
      Display name of the account.
    </ResponseField>
    <ResponseField name="role" type="integer" required>
      Role: `1` common user, `10` admin, `100` root.
    </ResponseField>
    <ResponseField name="status" type="integer" required>
      Account status: `1` enabled.
    </ResponseField>
    <ResponseField name="group" type="string" required>
      User group of the account.
    </ResponseField>
  </Expandable>

  <Expandable title="bind data structure">
    <ResponseField name="action" type="string" required>
      Always `bind` for the bind flow, indicating the GitHub identity was attached to the logged-in account.
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
  This endpoint is protected by a stricter rate limit (CriticalRateLimit). On successful login the response also sets the session cookie used by all console endpoints. Unlike most management endpoints, two failure modes are reported with non-200 status codes: unknown provider returns HTTP `400` and an empty/mismatched `state` returns HTTP `403`. GitHub must be enabled by the administrator (GitHub OAuth client id configured) before this flow works.
</Note>

## Error messages

| Condition | Description |
| --- | --- |
| Unknown OAuth provider | `provider` is not registered; HTTP `400` |
| State parameter is empty or mismatched | `state` missing or not matching the session; HTTP `403` |
| GitHub login and registration has not been enabled by administrator | GitHub OAuth is not configured/enabled |
| Provider error | `error`/`error_description` returned by GitHub; `error_description` is echoed in `message` |
| Unable to connect to GitHub server | Token exchange or profile fetch could not reach GitHub |
| Failed to get token from GitHub | Authorization code exchange failed, for example an invalid code |
| Failed to get user information / GitHub returned empty user info | Fetching the GitHub profile failed |
| New user registration has been disabled by administrator | No matching account exists and self-registration is disabled |
| User has been deleted | The linked account no longer exists |
| User has been banned | The linked account is not enabled |
| This GitHub account has already been bound | Another user already uses this GitHub identity |
| Database error, please try again later | Persisting the account or bind failed; see server logs |
