---
title: Get Channel Key
description: Reveal the full upstream key of a channel after passing security verification.
api: "POST /api/channel/{id}/key"
---

Return the full upstream key of a channel. This is the only channel endpoint that reveals the key, so it is locked down: it requires Root permissions, is subject to strict rate limiting, must not be cached, and the caller must have passed [security verification](/nookmux/api/management/security-verification/verify-post) beforehand — obtained from a `POST /api/verify` call made without a `scope`. Every call is recorded in the system log.

Requires **Root** permissions. See [Authentication](/nookmux/api/management/auth) for how to authenticate management API requests.

<Note>
  This endpoint is protected by strict rate limiting and by the security verification middleware: requests whose session holds no valid scopeless verification are rejected before the handler runs with HTTP `403` and a machine-readable `code` (`VERIFICATION_REQUIRED`, `VERIFICATION_INVALID`, or `VERIFICATION_EXPIRED`); a verification obtained with a `scope` set does not satisfy this guard. The verification is bound to the current user and stays valid for 300 seconds. Responses are sent with no-store cache directives.
</Note>

## Request

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/channel/1/key' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1'
```

</RequestExample>

### Path parameters

<ParamField path="id" type="integer" required>
  ID of the channel whose key should be revealed.
</ParamField>

## Response

<ResponseExample>

```json 200
{
  "success": true,
  "message": "Retrieved successfully",
  "data": {
    "key": "sk-xxxxxxxxxxxxxxxxxxxx"
  }
}
```

</ResponseExample>

### Response fields

<ResponseField name="success" type="boolean" required>
  Whether the key was returned.
</ResponseField>

<ResponseField name="message" type="string" required>
  Localized success message; error description when `success` is `false`.
</ResponseField>

<ResponseField name="data.key" type="string" required>
  The full upstream key stored on the channel. Multi-key channels return all keys joined by newlines.
</ResponseField>

<Note>
  Management endpoints return HTTP `200` even on business failures; always check the `success` field.
</Note>

## Error messages

| Condition | Description |
| --- | --- |
| Security verification required | HTTP `403` with `code: VERIFICATION_REQUIRED` / `VERIFICATION_INVALID` / `VERIFICATION_EXPIRED`: the session holds no valid scopeless verification; complete `POST /api/verify` without a `scope` first |
| Channel ID format error | `id` in the path is not an integer |
| Channel not found | No channel exists with the given ID |
| Failed to load channel info | The channel could not be loaded; see server logs |
