---
title: Pull Ollama Model
description: Trigger a blocking pull of a model on an Ollama channel's upstream server.
api: "POST /api/channel/ollama/pull"
---

Ask the Ollama server behind a channel to pull (download) a model. Only channels of type Ollama (`4`) are accepted; other channel types are rejected.

The pull is issued to the channel's upstream `/api/pull` endpoint with `stream: false`, so the HTTP request blocks until the Ollama server finishes downloading; because large models take a long time, the upstream request is given a 30-minute timeout. The upstream call goes through the proxy configured on the channel (settings `proxy`) and uses the first key of a multi-key channel. The channel's `base_url` overrides the built-in default (`http://localhost:11434`) when set. Use [Pull Ollama Model (Streaming)](/nookmux/api/management/channel-management/channel-ollama-pull-stream-post) to receive download progress instead of blocking.

Requires **Admin** permissions. See [Authentication](/nookmux/api/management/auth) for how to authenticate management API requests.

## Request

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/channel/ollama/pull' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1' \
  --header 'Content-Type: application/json' \
  --data '{
  "channel_id": 1,
  "model_name": "llama3.1:8b"
}'
```

</RequestExample>

### Body

<ParamField path="body.channel_id" type="integer" required>
  Id of the Ollama channel whose upstream server should pull the model.
</ParamField>

<ParamField path="body.model_name" type="string" required>
  Model tag to pull, as understood by the Ollama server, for example `llama3.1:8b`.
</ParamField>

## Response

<ResponseExample>

```json 200
{
  "success": true,
  "message": "Model llama3.1:8b pulled successfully"
}
```

</ResponseExample>

### Response fields

<ResponseField name="success" type="boolean" required>
  Whether the model was pulled.
</ResponseField>

<ResponseField name="message" type="string" required>
  Localized status text on success; error description when `success` is `false`.
</ResponseField>

<Note>
Unlike most management endpoints, this one reports failures with real HTTP status codes (`400`, `404`, `500`) instead of always returning `200`; the body keeps the `{ success, message }` shape, and no `data` field is returned on success. The request blocks until the download completes or the 30-minute upstream timeout expires.
</Note>

## Error messages

| Condition | Description |
| --- | --- |
| Invalid request parameters | HTTP 400 — the JSON body is malformed |
| Channel ID and model name are required | HTTP 400 — `channel_id` or `model_name` is missing |
| Channel not found | HTTP 404 — no channel exists with the given `channel_id` |
| Ollama channels only | HTTP 400 — the channel type is not Ollama |
| Failed to pull model | HTTP 500 — the upstream pull request failed or returned a non-200 status |
