---
title: Enable Tag Channel
description: Re-enable every channel carrying a given tag.
api: "POST /api/channel/tag/enabled"
---

Enable all channels that carry a given tag. Each matching channel's status is set to `1` (enabled) and the routing abilities for those channels are enabled accordingly, so requests can be routed to them again.

Requires **Admin** permissions. See [Authentication](/nookmux/api/management/auth) for how to authenticate management API requests.

## Request

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/channel/tag/enabled' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1' \
  --header 'Content-Type: application/json' \
  --data '{
  "tag": "openai-pool"
}'
```

</RequestExample>

### Body

<ParamField path="body.tag" type="string" required>
Tag whose channels should be enabled. Channels are matched by exact tag equality.
</ParamField>

## Response

<ResponseExample>

```json 200
{
  "success": true,
  "message": ""
}
```

</ResponseExample>

### Response fields

<ResponseField name="success" type="boolean" required>
Whether the channels were enabled.
</ResponseField>

<ResponseField name="message" type="string" required>
Error description when `success` is `false`; empty otherwise.
</ResponseField>

<Note>
Management endpoints return HTTP `200` even on business failures; always check the `success` field. This clears both manual and auto-disabled states for the matching channels. The channel cache is refreshed after the change.
</Note>

## Error messages

| Condition | Description |
| --- | --- |
| Invalid request parameters | The JSON body is missing, malformed, or `tag` is empty |
| Database error | Persisting the status change failed; see server logs |
