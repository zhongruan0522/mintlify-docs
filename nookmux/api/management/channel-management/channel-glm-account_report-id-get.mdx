---
title: Get GLM Account Report
description: Retrieve the Zhipu account funds report and persist the available balance to the channel.
api: "GET /api/channel/glm/account_report/{id}"
---

Retrieve the funds report of the Zhipu account behind a channel: current balance, cumulative recharge, system grants, cumulative spend, available balance, and frozen balance. The channel must be of the Zhipu type (`type` `26`, `ChannelTypeZhipu_v4`); plan channels are not required. Amounts are raw RMB values from the upstream.

On success, NookMux also persists the available balance (falling back to the current balance) to the channel record as its balance, in CNY, the same way the balance update endpoint does.

Requires **Admin** permissions. See [Authentication](/nookmux/api/management/auth) for how to authenticate management API requests.

## Request

<RequestExample>

```bash cURL
curl --request GET \
  --url 'https://your-nookmux-domain/api/channel/glm/account_report/1' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1'
```

</RequestExample>

### Path parameters

<ParamField path="id" type="integer" required>
Channel id.
</ParamField>

## Response

<ResponseExample>

```json 200
{
  "success": true,
  "data": {
    "balance": 18.52,
    "recharge_amount": 100.0,
    "give_amount": 10.0,
    "total_spend_amount": 91.48,
    "available_balance": 18.52,
    "frozen_balance": 0.0
  },
  "balance": 18.52,
  "currency": "CNY"
}
```

</ResponseExample>

### Response fields

<ResponseField name="success" type="boolean" required>
Whether the request succeeded.
</ResponseField>

<ResponseField name="data" type="object" required>
Funds report. Amounts are raw RMB values; every amount may be `null` when the upstream omits it.

<Expandable title="data structure">
  <ResponseField name="balance" type="number" required>
    Current balance. May be `null`.
  </ResponseField>
  <ResponseField name="recharge_amount" type="number" required>
    Cumulative cash recharge. May be `null`.
  </ResponseField>
  <ResponseField name="give_amount" type="number" required>
    System grants. May be `null`.
  </ResponseField>
  <ResponseField name="total_spend_amount" type="number" required>
    Cumulative cash spend. May be `null`.
  </ResponseField>
  <ResponseField name="available_balance" type="number" required>
    Active available balance, frozen amounts excluded. May be `null`.
  </ResponseField>
  <ResponseField name="frozen_balance" type="number" required>
    Frozen balance. May be `null`.
  </ResponseField>
</Expandable>
</ResponseField>

<ResponseField name="balance" type="number" required>
Balance value persisted to the channel record: `available_balance` when present, otherwise `balance`.
</ResponseField>

<ResponseField name="currency" type="string" required>
Currency of the persisted balance; always `CNY`.
</ResponseField>

<Note>
Management endpoints return HTTP `200` even on business failures; always check the `success` field. On success this endpoint returns `success`, `data`, `balance`, and `currency` (no `message` field); failures return `success: false` with a localized `message`.
</Note>

## Error messages

| Condition | message | Description |
| --- | --- | --- |
| Invalid parameters | `Invalid parameters` | `id` in the path is missing or not an integer |
| Channel not found | `Channel not found` | The channel does not exist or could not be loaded |
| Balance not implemented | `Not implemented yet` | The channel type is not Zhipu (`type` `26`) |
| Channel key invalid | `The channel API key is invalid or authentication failed. Please check the key configuration` | The upstream rejected the key |
| Quota query failed | `Failed to query quota: {{.Error}}` | The upstream request, response parsing, or balance picking failed; `{{.Error}}` carries the underlying error |
