---
title: Get Specific Redemption Code
description: Retrieve a single redemption code by id; the redemption key is masked in the response.
api: "GET /api/redemption/{id}"
---

Retrieve a single redemption code by its id. Redemption keys are redeemable credentials, so the `key` field is always returned as an empty string; the full key can only be fetched through the dedicated on-demand key endpoint.

Requires **Admin** permissions. See [Authentication](/nookmux/api/management/auth) for how to authenticate management API requests.

## Request

<RequestExample>

```bash cURL
curl --request GET \
  --url 'https://your-nookmux-domain/api/redemption/42' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1'
```

</RequestExample>

### Path parameters

<ParamField path="id" type="integer" required>
  Id of the redemption code.
</ParamField>

## Response

<ResponseExample>

```json 200
{
  "success": true,
  "message": "",
  "data": {
    "id": 42,
    "user_id": 1,
    "key": "",
    "status": 1,
    "name": "welcome-bonus",
    "quota": 100,
    "created_time": 1748000000,
    "redeemed_time": 0,
    "count": 0,
    "used_user_id": 0,
    "DeletedAt": null,
    "expired_time": 0
  }
}
```

</ResponseExample>

### Response fields

<ResponseField name="success" type="boolean" required>
  Whether the request succeeded.
</ResponseField>

<ResponseField name="message" type="string" required>
  Error description when `success` is `false`; empty otherwise.
</ResponseField>

<ResponseField name="data" type="object" required>
  The redemption code.

  <Expandable title="redemption structure">
    <ResponseField name="id" type="integer" required>
      Redemption code id.
    </ResponseField>
    <ResponseField name="user_id" type="integer" required>
      Id of the administrator who created the code.
    </ResponseField>
    <ResponseField name="key" type="string" required>
      The redemption key (a 32-character UUID without dashes). Always returned as an empty string by this endpoint; see the note below.
    </ResponseField>
    <ResponseField name="status" type="integer" required>
      Code status: `1` enabled, `2` disabled, `3` used.
    </ResponseField>
    <ResponseField name="name" type="string" required>
      Display name of the code.
    </ResponseField>
    <ResponseField name="quota" type="integer" required>
      Quota credited to the user who redeems the code.
    </ResponseField>
    <ResponseField name="created_time" type="integer" required>
      Unix timestamp (seconds) of creation.
    </ResponseField>
    <ResponseField name="redeemed_time" type="integer" required>
      Unix timestamp (seconds) of redemption; `0` if the code has not been redeemed.
    </ResponseField>
    <ResponseField name="count" type="integer" required>
      Number of codes to generate in one create call. Request-only field, always `0` in responses.
    </ResponseField>
    <ResponseField name="used_user_id" type="integer" required>
      Id of the user who redeemed the code; `0` if the code has not been redeemed.
    </ResponseField>
    <ResponseField name="DeletedAt" type="string" required>
      Soft-delete marker; always `null` because soft-deleted rows are excluded from queries.
    </ResponseField>
    <ResponseField name="expired_time" type="integer" required>
      Unix timestamp (seconds) after which the code can no longer be redeemed; `0` means no expiry.
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
Management endpoints return HTTP `200` even on business failures; always check the `success` field. The full redemption key is never returned by this endpoint; fetch it on demand from `GET /api/redemption/{id}/key`, which records the view in the operation logs.
</Note>

## Error messages

| Condition | Description |
| --- | --- |
| Invalid params | `id` is missing from the path or is not an integer |
| Database error | No redemption code exists with the given id, or loading it failed; see server logs |
