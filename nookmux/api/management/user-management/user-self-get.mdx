---
title: Get Current User Information
description: Return the profile, quota, invitation statistics, and notification settings of the logged-in user.
api: "GET /api/user/self"
---

Returns the profile of the user making the request: account identity, role and status, quota and usage counters, invitation statistics, bound OAuth identities, and the serialized notification settings. The user is resolved from the session or the access token together with the `New-Api-User` header.

Requires **User** permission (any logged-in user). See [Authentication](/nookmux/api/management/auth) for how to authenticate management API requests.

## Request

<RequestExample>

```bash cURL
curl --request GET \
  --url 'https://your-nookmux-domain/api/user/self' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 2'
```

</RequestExample>

### Response fields

<ResponseField name="success" type="boolean" required>
Whether the profile was returned.
</ResponseField>

<ResponseField name="message" type="string" required>
Error description when `success` is `false`; empty otherwise.
</ResponseField>

<ResponseField name="data" type="object" required>
Current user profile.

<Expandable title="data structure">
  <ResponseField name="id" type="integer" required>
User ID.
</ResponseField>
  <ResponseField name="username" type="string" required>
Login username.
</ResponseField>
  <ResponseField name="display_name" type="string" required>
Display name.
</ResponseField>
  <ResponseField name="role" type="integer" required>
Role level: `1` common user, `10` admin, `100` root.
</ResponseField>
  <ResponseField name="status" type="integer" required>
Account status: `1` enabled, `2` disabled.
</ResponseField>
  <ResponseField name="email" type="string" required>
Bound email address; empty when not bound.
</ResponseField>
  <ResponseField name="github_id" type="string" required>
Bound GitHub ID; empty when not bound.
</ResponseField>
  <ResponseField name="group" type="string" required>
User group, for example `default`.
</ResponseField>
  <ResponseField name="quota" type="integer" required>
Remaining quota in quota units (500,000 quota equals $1 by default).
</ResponseField>
  <ResponseField name="used_quota" type="integer" required>
Consumed quota in quota units.
</ResponseField>
  <ResponseField name="request_count" type="integer" required>
Total number of requests made by the user.
</ResponseField>
  <ResponseField name="aff_code" type="string" required>
Invitation code of this user.
</ResponseField>
  <ResponseField name="aff_count" type="integer" required>
Number of users registered with this user's invitation code.
</ResponseField>
  <ResponseField name="aff_quota" type="integer" required>
Remaining invitation reward quota that can still be converted.
</ResponseField>
  <ResponseField name="aff_history_quota" type="integer" required>
Accumulated invitation reward quota.
</ResponseField>
  <ResponseField name="inviter_id" type="integer" required>
User ID of the inviter; `0` when the user registered without an invitation code.
</ResponseField>
  <ResponseField name="linux_do_id" type="string" required>
Bound LinuxDO ID; empty when not bound.
</ResponseField>
  <ResponseField name="setting" type="string" required>
Notification settings serialized as a JSON string; see the expandable structure below. Empty fields are omitted; `gotify_priority` is always present, so a user without settings serializes as `{\"gotify_priority\":0}`. Written through `PUT /api/user/setting`.

<Expandable title="setting structure">
  <ResponseField name="notify_type" type="string">
Quota warning notification type: `email`, `webhook`, `bark`, or `gotify`.
</ResponseField>
  <ResponseField name="quota_warning_threshold" type="number">
Quota warning threshold.
</ResponseField>
  <ResponseField name="webhook_url" type="string">
Webhook URL, present for the `webhook` type.
</ResponseField>
  <ResponseField name="webhook_secret" type="string">
Webhook secret, present for the `webhook` type when configured.
</ResponseField>
  <ResponseField name="notification_email" type="string">
Notification email address, present for the `email` type when configured.
</ResponseField>
  <ResponseField name="bark_url" type="string">
Bark push URL, present for the `bark` type.
</ResponseField>
  <ResponseField name="gotify_url" type="string">
Gotify server URL, present for the `gotify` type.
</ResponseField>
  <ResponseField name="gotify_token" type="string">
Gotify application token, present for the `gotify` type.
</ResponseField>
  <ResponseField name="gotify_priority" type="integer">
Gotify message priority; always present in the serialized settings, `0` when unset.
</ResponseField>
</Expandable>
</ResponseField>
  <ResponseField name="stripe_customer" type="string" required>
Stripe customer ID used for online top-up; empty when not used.
</ResponseField>
  <ResponseField name="image_converted_count" type="integer" required>
Number of images converted by multimodal adaptation.
</ResponseField>
  <ResponseField name="video_converted_count" type="integer" required>
Number of videos converted by multimodal adaptation.
</ResponseField>
</Expandable>
</ResponseField>

<Note>
The endpoint builds the response explicitly: the password hash and the system access token are never returned, and the admin-only remark field is stripped, so it does not appear in the payload.
</Note>
