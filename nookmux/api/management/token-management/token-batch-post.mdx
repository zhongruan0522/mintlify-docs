---
title: Batch Delete Tokens
description: Delete several tokens owned by the current user in one call and return the number removed.
api: "POST /api/token/batch"
---

Delete multiple tokens owned by the current user in a single transaction. Ids that do not exist or belong to another user are silently skipped and not counted; the response returns the number of tokens actually deleted.

Requires a logged-in user (**User** permissions). See [Authentication](/nookmux/api/management/auth) for how to authenticate management API requests.

## Request

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/token/batch' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1' \
  --header 'Content-Type: application/json' \
  --data '{
  "ids": [1, 2, 3]
}'
```

</RequestExample>

### Body

<ParamField path="body.ids" type="integer[]" required>
  Ids of the tokens to delete. Must be a non-empty array; only tokens owned by the current user are matched.
</ParamField>

## Response

<ResponseExample>

```json 200
{
  "success": true,
  "message": "",
  "data": 2
}
```

</ResponseExample>

### Response fields

<ResponseField name="success" type="boolean" required>
  Whether the batch deletion completed.
</ResponseField>

<ResponseField name="message" type="string" required>
  Error description when `success` is `false`; empty otherwise.
</ResponseField>

<ResponseField name="data" type="integer" required>
  Number of tokens actually deleted. Ids that were not found among the current user's tokens do not count.
</ResponseField>

<Note>
Management endpoints return HTTP `200` even on business failures; always check the `success` field.
</Note>

## Error messages

| Condition | Description |
| --- | --- |
| Invalid parameters | The JSON body is malformed or `ids` is empty |
| Database error | The batch deletion failed; see server logs |
