---
title: Force Garbage Collection
description: Trigger a full garbage collection cycle in the gateway process.
api: "POST /api/performance/gc"
---

Runs a full garbage collection cycle in the NookMux process (Go runtime `runtime.GC`) and returns after it completes. Useful for returning memory to the OS after clearing caches or processing large batches. The operation is recorded in the audit log.

Requires **Root** (super administrator) permissions. See [Authentication](/nookmux/api/management/auth) for how to authenticate management API requests.

## Request

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/performance/gc' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1'
```

</RequestExample>

## Response

<ResponseExample>

```json 200
{
  "success": true,
  "message": "GC has been executed"
}
```

</ResponseExample>

### Response fields

<ResponseField name="success" type="boolean" required>
  Whether the garbage collection cycle ran.
</ResponseField>

<ResponseField name="message" type="string" required>
  Confirmation text on success, localized according to the caller's language preference.
</ResponseField>

<Note>
Management endpoints return HTTP `200` even on business failures; always check the `success` field. This endpoint has no business failure path. The garbage collection runs synchronously before the response is returned.
</Note>

## Error messages

| Condition | Description |
| --- | --- |
| Authentication failed | Standard authentication errors (HTTP `401`) when the caller is not a root user |
