---
title: Get Logs by Token Key
description: Query the usage logs of the token key presented in the Authorization header, with a paginated and a legacy array mode.
api: "GET /api/log/token"
---

Return the usage logs of the API token whose key is presented in the request. The token id is forced from the authenticated token, so a caller can never read the logs of another token. This endpoint is authenticated by the token key itself — the `Authorization` header must carry the token key (for example `sk-xxxx`), not a management access token.

The token is resolved by the read-only token authentication middleware, which only checks that the key exists: disabled, expired or exhausted tokens are still accepted; banned users are rejected. See [Authentication](/nookmux/api/management/auth) for the general authentication model of the management API.

<Note>
This route is protected by the strict critical rate limit and allows cross-origin requests (CORS). Passing either `p` or `page_size` switches the endpoint to the paginated response; when both are absent, the legacy response of a plain recent-logs array is kept.
</Note>

## Request

<RequestExample>

```bash cURL
curl --request GET \
  --url 'https://your-nookmux-domain/api/log/token?p=1&page_size=10&type=2&model_name=gpt-4o' \
  --header 'Authorization: Bearer sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx'
```

</RequestExample>

### Headers

<ParamField path="header.Authorization" type="string" required>
  The API token key, in the form `Bearer sk-xxxx`.
</ParamField>

### Query parameters

<ParamField path="query.p" type="integer" default="1">
  Page number. Passing `p` or `page_size` switches the endpoint to the paginated response.
</ParamField>

<ParamField path="query.page_size" type="integer" default="10">
  Items per page, capped at 100. The pagination helper also accepts the legacy aliases `ps` and `size`.
</ParamField>

<ParamField path="query.type" type="integer">
  Log type: `1` top-up, `2` consumption, `3` manage, `4` system, `5` error, `6` refund. Omitted or `0` matches all types. Only applied in paginated mode.
</ParamField>

<ParamField path="query.start_timestamp" type="integer">
  Unix timestamp (seconds); only logs with `created_at` greater than or equal to this value are returned. `0` (default) means no lower bound. Only applied in paginated mode.
</ParamField>

<ParamField path="query.end_timestamp" type="integer">
  Unix timestamp (seconds); only logs with `created_at` less than or equal to this value are returned. `0` (default) means no upper bound. Only applied in paginated mode.
</ParamField>

<ParamField path="query.model_name" type="string">
  Model name pattern; `%` wildcards are allowed (at most two, not consecutive, and the keyword without `%` must be at least 2 characters), `_` and `!` are matched literally. Without `%` the model name must match exactly. Only applied in paginated mode.
</ParamField>

<Note>
Legacy array mode: when neither `p` nor `page_size` is present, `data` is a plain array of up to 1000 recent logs of the token (same log structure and sanitization, `id` numbered from 1) instead of the pagination object, and the type, timestamp and model filters are not applied.
</Note>

<Note>
Management endpoints return HTTP `200` even on business failures; authentication failures on this route return HTTP `401` / `403` / `500` instead.
</Note>

## Error messages

| Condition | Status | Description |
| --- | --- | --- |
| No Authorization header | `401` | The `Authorization` header is missing |
| Invalid token | `401` | The key does not match any token |
| User has been banned | `403` | The token owner is disabled |
| Database error, please try again later | `500` | Loading the token owner's user cache failed |
| Database error, please try again later | `200` | Querying or counting the logs failed; see server logs |
