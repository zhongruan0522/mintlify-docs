---
title: Initiate Easy Payment
description: Create an Epay top-up order and get the signed parameters for the gateway cashier.
api: "POST /api/user/pay"
---

Initiates an online top-up through the configured Epay gateway. The server computes the payable amount for the requested quantity, creates a pending top-up order, and returns the signed submit parameters together with the gateway URL that the client opens to display the cashier. The order is credited later by the Epay callback (`GET /api/user/epay/notify`).

Requires **User** permissions (any logged-in account). See [Authentication](/nookmux/api/management/auth) for how to authenticate management API requests.

<Note>
This endpoint applies a stricter per-IP rate limit (CriticalRateLimit, when enabled); exceeding it returns HTTP `429`.
</Note>

## Request

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/user/pay' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1' \
  --header 'Content-Type: application/json' \
  --data '{
  "amount": 10,
  "payment_method": "alipay"
}'
```

</RequestExample>

### Body

<ParamField path="body.amount" type="integer" required>
Top-up quantity. Must not be lower than the configured minimum top-up amount.
</ParamField>

<ParamField path="body.payment_method" type="string" required>
Payment channel type, matching one of the `type` values in `pay_methods` returned by `GET /api/user/topup/info`, for example `alipay` or `wxpay`.
</ParamField>

## Response

<ResponseExample>

```json 200
{
  "success": true,
  "message": "Top-up successful",
  "data": {
    "pid": "1000",
    "type": "alipay",
    "out_trade_no": "USR1NOAb12cd1730000000",
    "notify_url": "https://your-nookmux-domain/api/user/epay/notify",
    "name": "TUC10",
    "money": "73.00",
    "device": "pc",
    "sign_type": "MD5",
    "return_url": "https://your-nookmux-domain/console/log",
    "sign": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
  },
  "url": "https://epay-gateway-example.com/submit.php"
}
```

</ResponseExample>

### Response fields

<ResponseField name="success" type="boolean" required>
Whether the order was created and the payment parameters were generated.
</ResponseField>

<ResponseField name="message" type="string" required>
Localized status message; error description when `success` is `false`. The exact wording depends on the request language.
</ResponseField>

<ResponseField name="data" type="object" required>
Signed Epay submit parameters for the created order.

<Expandable title="data structure">
  <ParamField path="pid" type="string" required>
    Merchant ID configured for the Epay gateway.
  </ParamField>
  <ParamField path="type" type="string" required>
    Payment channel, equal to the requested `payment_method`.
  </ParamField>
  <ParamField path="out_trade_no" type="string" required>
    Order number of the created top-up order, in the form `USR{user_id}NO{6 random characters}{unix timestamp}`.
  </ParamField>
  <ParamField path="notify_url" type="string" required>
    Callback URL the gateway notifies after the payment completes.
  </ParamField>
  <ParamField path="name" type="string" required>
    Product name, in the form `TUC{amount}`.
  </ParamField>
  <ParamField path="money" type="string" required>
    Payable amount with two decimal places.
  </ParamField>
  <ParamField path="device" type="string" required>
    Device type of the cashier; `pc`.
  </ParamField>
  <ParamField path="sign_type" type="string" required>
    Signature algorithm; `MD5`.
  </ParamField>
  <ParamField path="return_url" type="string" required>
    URL the gateway redirects the user to after the payment (the console log page).
  </ParamField>
  <ParamField path="sign" type="string" required>
    MD5 signature over the sorted parameters.
  </ParamField>
</Expandable>
</ResponseField>

<ResponseField name="url" type="string" required>
Submit URL on the Epay gateway (`{gateway_address}/submit.php`). Send the `data` parameters to this URL to open the cashier.
</ResponseField>

## Error messages

| Condition | Description |
| --- | --- |
| Invalid parameters | The JSON body is missing or malformed |
| Top-up amount cannot be less than the minimum | `amount` is lower than the configured minimum top-up amount |
| Failed to get user group | The caller's top-up group could not be loaded |
| Top-up amount is too low | The computed payable amount is below the minimum chargeable amount (0.01) |
| Payment method does not exist | `payment_method` is not one of the configured payment methods |
| Payment information is not configured | The Epay gateway address, merchant ID or key is missing on the server |
| Failed to initiate payment | The gateway rejected the purchase request |
| Failed to create order | Persisting the top-up order failed; see server logs |
