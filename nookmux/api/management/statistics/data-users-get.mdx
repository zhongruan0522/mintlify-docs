---
title: Get User Analytics Data
description: Query the pre-aggregated usage dashboard grouped per user, used by the user analytics charts.
api: "GET /api/data/users"
---

Returns the pre-aggregated dashboard dataset grouped by user, used by the user analytics charts. Rows aggregate all models per `username` and hourly time bucket across the whole deployment. The underlying `quota_data` table is flushed periodically from request logs, so recent usage may lag by the quota data refresh interval configured in Dashboard Configuration.

Requires **Admin** permissions. See [Authentication](/nookmux/api/management/auth) for how to authenticate management API requests.

## Request

<RequestExample>

```bash cURL
curl --request GET \
  --url 'https://your-nookmux-domain/api/data/users?start_timestamp=1735689600&end_timestamp=1738368000' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1'
```

</RequestExample>

### Query parameters

<ParamField path="start_timestamp" type="integer">
  Unix timestamp (seconds) of the range start, compared against the hourly bucket timestamps. Optional; omit or pass `0` to skip the lower bound.
</ParamField>

<ParamField path="end_timestamp" type="integer">
  Unix timestamp (seconds) of the range end. Optional; omit or pass `0` to skip the upper bound.
</ParamField>

```json 200
    }
  ]
}
```

</ResponseExample>

### Response fields

<ResponseField name="success" type="boolean" required>
  Whether the query succeeded.
</ResponseField>

<ResponseField name="message" type="string" required>
  Error description when `success` is `false`; empty otherwise.
</ResponseField>

<ResponseField name="data" type="array" required>
  Aggregated usage rows, one per `username` and hourly `created_at` bucket.

  <Expandable title="user analytics row structure">
    <ResponseField name="username" type="string" required>
      Username the row aggregates.
    </ResponseField>
    <ResponseField name="created_at" type="integer" required>
      Unix timestamp (seconds) of the hourly bucket.
    </ResponseField>
    <ResponseField name="count" type="integer" required>
      Number of successful requests in the bucket.
    </ResponseField>
    <ResponseField name="fail_count" type="integer" required>
      Number of failed requests in the bucket.
    </ResponseField>
    <ResponseField name="token_used" type="integer" required>
      Total tokens consumed in the bucket.
    </ResponseField>
    <ResponseField name="quota" type="integer" required>
      Total quota consumed in the bucket.
    </ResponseField>
    <ResponseField name="id" type="integer" required>
      Always `0`: rows are aggregated, so the row identity is not populated.
    </ResponseField>
    <ResponseField name="user_id" type="integer" required>
      Always `0`: rows are grouped by username, not by user ID.
    </ResponseField>
    <ResponseField name="model_name" type="string" required>
      Always empty: this endpoint aggregates across all models.
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
  When user analytics is disabled in the dashboard configuration, the endpoint returns `success: true` with the message `User analytics is disabled` and an empty `data` array instead of an error. When both timestamps are provided, the range must not exceed the configured maximum (31 days by default); the rejection message text is fixed regardless of the configured maximum.

  Results are served from a per-time-window snapshot cache refreshed at most once per `user_analytics_refresh_interval` (3600 seconds by default, floor 60 seconds); data recalculated for the same window appears only after the cache expires.
</Note>

## Error messages

| Condition | Description |
| --- | --- |
| The time range cannot exceed 1 month | `end_timestamp - start_timestamp` exceeds the configured maximum query window |
| Database error, please try again later | Querying `quota_data` failed; see server logs |
