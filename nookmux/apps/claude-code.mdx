## Install

macOS / Linux:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows (PowerShell):

```powershell
irm https://claude.ai/install.ps1 | iex
```

You can also install it with a package manager: `brew install --cask claude-code`, `winget install Anthropic.ClaudeCode`, or `npm install -g @anthropic-ai/claude-code@latest`.

```bash
# Verify
claude --version
```

Claude Code runs natively on Windows (install Git for Windows as well) and also works inside WSL.

## Connect to NookMux

Claude Code uses environment variables to point at the gateway. NookMux provides an Anthropic Messages-compatible endpoint. The minimum setup uses two variables:

| Environment Variable | Value |
| --- | --- |
| `ANTHROPIC_BASE_URL` | NookMux site root, for example `https://your-domain.com` (do not include `/v1/messages`) |
| `ANTHROPIC_AUTH_TOKEN` | NookMux token (starts with the site key prefix, default `sk-`) |

NookMux's Anthropic-compatible endpoint accepts both authentication headers below. They correspond to Claude Code's two credential variables; use either one:

| Environment Variable | Header Sent |
| --- | --- |
| `ANTHROPIC_AUTH_TOKEN` | `Authorization: Bearer <token>` |
| `ANTHROPIC_API_KEY` | `x-api-key: <token>` |

Once `ANTHROPIC_BASE_URL` is set, every model request goes to NookMux and is billed against your NookMux token instead of your Anthropic account quota.

macOS / Linux:

```bash
export ANTHROPIC_BASE_URL=https://your-domain.com
export ANTHROPIC_AUTH_TOKEN=sk-your-nookmux-token
claude
```

To make it persistent, add the two lines to `~/.zshrc` or `~/.bashrc`, then `source` the file.

Windows (PowerShell):

```powershell
$env:ANTHROPIC_BASE_URL = "https://your-domain.com"
$env:ANTHROPIC_AUTH_TOKEN = "sk-your-nookmux-token"
claude
```

### Store the Variables in the Settings File

You can also put the variables in the `env` block of the user-level settings file `~/.claude/settings.json` (`%USERPROFILE%\.claude\settings.json` on Windows):

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://your-domain.com",
    "ANTHROPIC_AUTH_TOKEN": "sk-your-nookmux-token"
  }
}
```

Values in the `env` block take precedence over variables exported in the terminal.

<Card type="warning" title="Do not commit the token to a repository">
  Keep the token in your terminal environment, in the user-level `~/.claude/settings.json`, or in a `.claude/settings.local.json` that is listed in `.gitignore`. Do not put it in a `.claude/settings.json` that gets committed with the repository.
</Card>

### Get the Token from NookMux

1. Create or select a token on the console's "Keys" page and copy the full secret. It starts with the site key prefix (default `sk-`).
2. Make sure the channel already has the `claude-*` models you want to use.

## Verify the Connection

Before starting Claude Code, send a minimal request to the gateway to confirm the configuration:

```bash
curl -X POST "$ANTHROPIC_BASE_URL/v1/messages" \
  -H "Authorization: Bearer $ANTHROPIC_AUTH_TOKEN" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model": "claude-sonnet-4-6", "max_tokens": 1, "messages": [{"role": "user", "content": "."}]}'
```

If the response starts with `{"id":"msg_`, the address and token are valid. Then run `claude` and open the **Status** tab of `/status`. When a gateway address is set, the tab includes an `Anthropic base URL` row; confirm that it points to your NookMux site.

## Usage

```bash
cd /path/to/your/project
claude
```

## Choose a Model

Claude Code sends the model name to the gateway as is, so you can pick a preset Claude model in `/model` or use any model configured in the NookMux channel:

```bash
# Switch inside a session
/model glm-5.4

# Pick a model at startup
claude --model claude-sonnet-4-6

# Set the default with an environment variable
export ANTHROPIC_MODEL=glm-5.4
```

Presets such as Sonnet and Opus resolve to concrete Claude model names before they are sent to NookMux, so make sure those models exist in the channel.

<Info>
  <b>Show NookMux models in /model</b>
  Claude Code can fetch the model list from a gateway, but this is off by default. Set the environment variable `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`, and Claude Code requests NookMux's `/v1/models` at startup and adds every returned model whose ID contains `claude` or `anthropic` to the `/model` picker.
</Info>

`ANTHROPIC_BASE_URL` only changes where requests are sent; the model you choose is still the one that answers.

## Common Issues

### 401 / Invalid Token

- Make sure the token is the full NookMux token starting with the site key prefix (default `sk-`).
- If Claude Code warns that auth may not work as expected, another credential is still active, such as a leftover claude.ai login. Run `/logout` to clear the login, or unset the credential variables you do not need, then try again.

### curl works but Claude Code still asks you to log in

- Variables that live only in a project-level settings file take effect after the first-run wizard. Move them to the user-level `~/.claude/settings.json` or to your terminal environment.
- With `ANTHROPIC_API_KEY`, interactive mode asks you once to confirm that the key should be used. If you declined earlier, turn `Use custom API key` back on in `/config`.

### Requests rejected with 400

Claude Code sends a few pre-release parameters that some upstreams reject. Handle them by the error text:

| Error | Fix |
| --- | --- |
| `context_management` or `Extra inputs are not permitted` | Set `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` |
| `thinking` or `adaptive` | Claude Code usually retries automatically; if it keeps failing, set `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING=1` |
| Context window exceeded | Run `/compact`, or lower the auto-compact window with `CLAUDE_CODE_AUTO_COMPACT_WINDOW` |
| 403 with an HTML body | A WAF on the site is inspecting request bodies; check its firewall rules |
| Certificate errors | Point `NODE_EXTRA_CA_CERTS` to your CA certificate file |

### Feature availability

With gateway credentials, Remote Control and voice dictation are unavailable.
