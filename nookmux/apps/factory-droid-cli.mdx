## Install

macOS / Linux:

```bash
curl -fsSL https://app.factory.ai/cli | sh
```

Windows (PowerShell):

```powershell
irm https://app.factory.ai/cli/windows | iex
```

npm (requires Node.js 20 or later):

```bash
npm install -g droid
```

```bash
# Verify the installation
droid --version
```

The macOS / Linux script installs `droid` to `~/.local/bin`; follow the prompt to add that directory to your PATH. Linux needs `xdg-utils` installed. The Windows script installs `droid.exe` to `%USERPROFILE%\bin` and adds it to the user PATH automatically. The first time you start `droid`, sign in through your browser with a Factory account (free) if prompted.

## Connect to NookMux

Droid CLI configures custom models through the `customModels` array in `~/.factory/settings.json` (`%USERPROFILE%\.factory\settings.json` on Windows). NookMux provides an OpenAI-compatible interface:

```json
{
  "customModels": [
    {
      "model": "gpt-5.6",
      "displayName": "NookMux GPT",
      "baseUrl": "https://your-domain.com/v1",
      "apiKey": "${NOOKMUX_API_KEY}",
      "provider": "generic-chat-completion-api",
      "maxOutputTokens": 16384
    }
  ]
}
```

| Field | Description |
| --- | --- |
| `model` | Required. Must match the model name configured in the NookMux channel |
| `provider` | Required. The API protocol; see the values below |
| `baseUrl` | Required. NookMux site address + `/v1`; use the site root when `provider` is `anthropic` |
| `displayName` | Name shown in the `/model` list |
| `apiKey` | Supports `${VAR_NAME}` syntax to reference an environment variable |
| `maxOutputTokens` / `maxContextLimit` | Optional. Maximum output tokens and the model's context window (input tokens); set them to the model's real limits |

Values for `provider`:

- `generic-chat-completion-api`: OpenAI Chat Completions-compatible (works for most cases).
- `openai`: OpenAI Responses API.
- `anthropic`: Anthropic Messages API. Set `baseUrl` to the NookMux site root and use a `claude-*` model.

Anthropic model example:

```json
{
  "customModels": [
    {
      "model": "claude-sonnet-4-5-20250929",
      "displayName": "NookMux Claude",
      "baseUrl": "https://your-domain.com",
      "apiKey": "${NOOKMUX_API_KEY}",
      "provider": "anthropic",
      "maxOutputTokens": 16384
    }
  ]
}
```

## Usage

1. Create a token on the NookMux console's "Keys" page and copy the full secret, which starts with the site key prefix (default `sk-`).
2. Export the environment variable:

   ```bash
   export NOOKMUX_API_KEY=sk-your-nookmux-token
   ```

3. Start Droid CLI:

   ```bash
   cd /path/to/your/project
   droid
   ```

4. Use the `/model` command to pick the configured model from the "Custom Models" group. You can also add and manage custom models under Custom models in `/settings`.

## Common Issues

### The Model Does Not Appear in the Selector

- Check that `~/.factory/settings.json` is valid JSON.
- Make sure the required fields `model`, `provider`, and `baseUrl` are complete.

### Authentication Failed

- Confirm the environment variable is exported and matches the `${...}` reference in `apiKey`.
- Confirm the token is a full NookMux secret starting with the site key prefix (default `sk-`) and has not been disabled.

### PowerShell Execution Policy Restriction

Download the script and bypass the execution policy for that one run:

```powershell
curl.exe -fsSL https://app.factory.ai/cli/windows -o install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
del install.ps1
```
