title: Security & Limits
description: Model request rate limiting and per-group overrides under Security & Limits, a group that also covers sensitive words, SSRF protection, and audit logs.
---

The old "Rate Limit Settings" page is now under **System Settings → Security & Limits → Rate Limit**.

Configurable items include:

- Whether model request rate limiting is enabled.
- Maximum requests per limit window.
- Maximum successful requests per limit window.
- Limit window length in minutes.
- Group-based rate limit overrides.

The two limits are counted separately for each user. *Maximum requests per limit window* counts every admitted request, including failed ones, and `0` means unlimited. *Maximum successful requests per limit window* counts only requests that complete with a status code below 400, so failed requests never use up this quota. A request holds one slot of this limit while it is being processed and gives the slot back if it fails, so requests being processed at the same time plus the successful requests already inside the window never exceed the configured number. A request rejected by either limit is not counted toward any limit. A limit window of `0` minutes disables both limits.

Both limits use a sliding window: within the limit window leading up to the current moment, no more than the configured number of requests is counted. A request beyond either limit gets a `429` response whose body names the limit that was reached and whose `Retry-After` header gives the suggested wait in seconds (one full limit window).

Group rate limit example:

```json
{
  "default": [200, 100],
  "vip": [0, 1000]
}
```

Refer to the field descriptions on the page for the exact meaning of each value in a group entry. The Security & Limits group also includes sensitive words, SSRF protection, and audit log settings.
