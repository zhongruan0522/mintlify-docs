title: Docker Compose 配置说明
---

本文档说明当前 NookMux `docker-compose.yml` 的结构和常见扩展方式。根目录实际配置以 `docker-compose.yml` 为准：默认启动 NookMux 与 Redis，不内置 MySQL/PostgreSQL 服务；如需外部数据库，请设置 `SQL_DSN`。

## 当前推荐配置

```yaml
services:
  nookmux:
    image: ghcr.io/nookmux/nookmux:latest
    container_name: nookmux
    restart: always
    command: --log-dir /app/logs
    ports:
      - "3000:3000"
    volumes:
      - ./data:/data
      - ./logs:/app/logs
    environment:
      - REDIS_CONN_STRING=redis://:change_this_password@redis:6379
      - TZ=Asia/Shanghai
      - ERROR_LOG_ENABLED=true
      - BATCH_UPDATE_ENABLED=true
      - SESSION_SECRET=replace_with_a_random_string
      - CRYPTO_SECRET=replace_with_another_random_string
    depends_on:
      redis:
        condition: service_healthy

  redis:
    image: redis:latest
    container_name: redis
    restart: always
    command: ["redis-server", "--requirepass", "change_this_password"]
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "change_this_password", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
```

<Card type="warning" title="不要直接使用示例密码">
  示例中的 `change_this_password`、`replace_with_a_random_string` 都必须替换为生产环境专用的随机值。
</Card>

## NookMux 服务字段说明

| 参数 | 说明 |
| --- | --- |
| `image` | 官方镜像，当前为 `ghcr.io/nookmux/nookmux:latest`。 |
| `container_name` | 容器名称，默认示例为 `nookmux`。 |
| `command` | 启动参数。`--log-dir /app/logs` 将日志目录指向持久化路径。 |
| `ports` | 端口映射，默认 `3000:3000`。 |
| `volumes` | 数据和日志持久化。至少应挂载 `/data`。 |
| `environment` | 环境变量配置，见[环境变量配置指南](/cn/nookmux/installation/config-maintenance/environment-variables)。 |
| `depends_on` | 等待 Redis 健康后启动应用。 |
| `healthcheck` | 可选健康检查，检查 `/api/status` 是否返回成功。 |

## 数据库配置

### 默认 SQLite

不设置 `SQL_DSN` 时使用 SQLite，数据库路径默认是 `/data/one-api.db`。这适合个人或小规模部署。

### 外部 MySQL

```yaml
environment:
  - SQL_DSN=mysql://user:password@mysql-host:3306/nookmux
```

### 外部 PostgreSQL

```yaml
environment:
  - SQL_DSN=postgres://user:password@postgres-host:5432/nookmux
```

### 外部 openGauss

```yaml
environment:
  # 目标库需以 DBCOMPATIBILITY='PG' 创建；口令含特殊字符时按 URL 规则 percent-encode
  - SQL_DSN=opengauss://user:password@opengauss-host:5432/nookmux
```

### 外部达梦 DM8

```yaml
environment:
  # 实例需以 CASE_SENSITIVE=N 初始化并运行于 DM 原生模式（COMPATIBLE_MODE=0，dm.ini 参数），账号需 SELECT ANY DICTIONARY 权限；口令按字面值写入，不得包含 ?（: 与 @ 可用）
  - SQL_DSN=dm://user:password@dm-host:5236?schema=NOOKMUX
```

### 外部金仓 KingbaseES

```yaml
environment:
  # Oracle 兼容模式；实例不得开启 enable_ci（否则启动时被拒绝）；口令按 URL 规则 percent-encode
  - SQL_DSN=kingbase://user:password@kingbase-host:54321/nookmux?sslmode=disable
  # 生产容量建议：连接池上限按实例会话上限显著调低
  # - SQL_MAX_OPEN_CONNS=50
  # - SQL_PREPARE_STMT=true
```

生产环境容量建议：

- 金仓默认 `max_connections=100`。主库与日志库各持有独立连接池、默认上限各为 1000（`SQL_MAX_OPEN_CONNS`），请按实例会话上限显著调低，否则高峰期新连接将以 `FATAL 53300: sorry, too many clients already` 失败。
- 未开启 SSL 的实例须在 DSN 中保留 `sslmode=disable`：Gokb 驱动默认 `require` 且无明文回退。
- Gokb 默认路径每条带参 SQL 需两次往返且无语句缓存，生产负载建议开启 `SQL_PREPARE_STMT=true`。

NookMux 后端需要兼容 SQLite、MySQL、PostgreSQL、openGauss（7.0，PG 兼容内核）、达梦 DM8 和金仓 KingbaseES。请确保数据库字符集和权限满足生产需求。

## Redis 配置

```yaml
environment:
  - REDIS_CONN_STRING=redis://:password@redis:6379
```

Redis 可用于缓存和多节点同步。若不配置 Redis，单节点仍可运行，但多节点部署必须共享同一个 Redis。

## 多节点部署入口

多节点部署需要所有节点共享同一数据库、同一 Redis，以及相同的 `SESSION_SECRET` / `CRYPTO_SECRET`。从节点额外设置：

```yaml
environment:
  - NODE_TYPE=slave
  - FRONTEND_BASE_URL=https://your-domain.example.com
```

完整示例请参考[集群部署](/cn/nookmux/installation/deployment-methods/cluster-deployment)。

## 常用命令

```bash
docker compose up -d
docker compose ps
docker compose logs -f nookmux
docker compose pull && docker compose up -d
docker compose down
```
