本文档提供 NookMux 多节点部署的配置步骤和最佳实践，帮助您构建高可用、负载均衡的分布式系统。

## 前置要求

- 多台服务器（至少两台，一主多从架构）
- 已安装 Docker 和 Docker Compose
- 共享的 MySQL、PostgreSQL、openGauss、达梦 DM8 或金仓 KingbaseES 数据库（所有节点访问同一数据库）
- 共享的 Redis 服务（用于节点间数据同步和缓存）
- 可选：负载均衡器（如 Nginx、HAProxy 或云负载均衡）

<Card type="info" title="数据库选择">
  多节点场景下不要使用 SQLite。请使用外部数据库（MySQL、PostgreSQL、openGauss、达梦 DM8 或金仓 KingbaseES），并确保所有节点使用相同的 `SQL_DSN`。
</Card>

## 集群架构概述

NookMux 多节点部署采用主从架构：

1. **主节点**（`NODE_TYPE` 默认 `master`）：负责数据库迁移、根账号创建、定时渠道测试等管理任务，并处理流量。
2. **从节点**（`NODE_TYPE=slave`）：跳过数据库迁移和定时任务，主要负责处理流量，提高系统整体吞吐量。

从节点仍会接收并处理写请求（如管理操作），因此多节点环境必须保证所有节点共享同一数据库与 Redis，避免数据不一致。

## 集群部署关键配置

集群部署的关键在于所有节点必须：

1. **共享相同的数据库**：所有节点使用同一 `SQL_DSN`
2. **共享相同的 Redis**：用于缓存和节点间通信
3. **使用相同的密钥**：`SESSION_SECRET` 和 `CRYPTO_SECRET` 必须在所有节点上相同
4. **正确配置节点类型**：主节点不设置或设为 `master`，从节点设为 `slave`
5. **从节点设置 `FRONTEND_BASE_URL`**：从节点的非 API 请求会重定向到该地址（通常指向主节点域名）

## 部署步骤

### 步骤一：准备共享数据库和 Redis

准备外部 MySQL/PostgreSQL/openGauss/DM8/金仓 KingbaseES 和 Redis 服务。可以是：

- 单独部署的高可用数据库和 Redis
- 云服务商提供的托管服务
- 独立服务器上运行的自建服务

应用程序的 `SQL_DSN` 只需要一个统一入口地址；如果数据库自身做了主从或代理层负载均衡，请在数据库侧完成配置。

### 步骤二：配置主节点

在主节点服务器上创建 `docker-compose.yml`：

```yaml
services:
  nookmux-master:
    image: ghcr.io/nookmux/nookmux:latest
    container_name: nookmux-master
    restart: always
    command: --log-dir /app/logs
    ports:
      - '3000:3000'
    environment:
      - SQL_DSN=postgres://user:password@your-db-host:5432/nookmux
      - REDIS_CONN_STRING=redis://:password@your-redis-host:6379
      - SESSION_SECRET=your_unique_session_secret
      - CRYPTO_SECRET=your_unique_crypto_secret
      - TZ=Asia/Shanghai
      # 可选配置
      - SYNC_FREQUENCY=60
    volumes:
      - ./data:/data
      - ./logs:/app/logs
```

启动主节点：

```bash
docker compose up -d
```

### 步骤三：配置从节点

在每个从节点服务器上创建 `docker-compose.yml`：

```yaml
services:
  nookmux-slave:
    image: ghcr.io/nookmux/nookmux:latest
    container_name: nookmux-slave
    restart: always
    command: --log-dir /app/logs
    ports:
      - '3000:3000' # 可与主节点使用相同端口，因为它们在不同服务器上
    environment:
      - SQL_DSN=postgres://user:password@your-db-host:5432/nookmux # 与主节点相同
      - REDIS_CONN_STRING=redis://:password@your-redis-host:6379 # 与主节点相同
      - SESSION_SECRET=your_unique_session_secret # 必须与主节点相同
      - CRYPTO_SECRET=your_unique_crypto_secret # 必须与主节点相同
      - NODE_TYPE=slave # 关键配置，指定为从节点
      - FRONTEND_BASE_URL=https://your-domain.com # 指向主节点的对外地址
      - TZ=Asia/Shanghai
      # 可选配置
      - SYNC_FREQUENCY=60
    volumes:
      - ./data:/data
      - ./logs:/app/logs
```

启动从节点：

```bash
docker compose up -d
```

对每台从节点服务器重复此步骤。

### 步骤四：配置负载均衡

以下是使用 Nginx 作为负载均衡器的配置示例：

```nginx
upstream nookmux_cluster {
    server master-node-ip:3000 weight=3;
    server slave-node1-ip:3000 weight=5;
    server slave-node2-ip:3000 weight=5;
}

server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://nookmux_cluster;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # SSE/流式响应需要关闭缓冲
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
```

<Card type="info" title="真实客户端 IP">
  使用反向代理或 CDN 时，请配置 `TRUSTED_PROXIES` 环境变量，确保限流和日志使用真实客户端 IP。默认值为 `private,cloudflare`；位于公网地址的反向代理或 CDN 需要显式加入，否则所有访客都会被计为该地址并共用同一份额度，日志会给出该地址的提示。
</Card>

## 高级配置选项

### 数据同步设置

| 环境变量 | 说明 | 推荐值 |
| --- | --- | --- |
| `SYNC_FREQUENCY` | 缓存与数据库同步频率（秒） | `60` |
| `BATCH_UPDATE_ENABLED` | 启用数据库批量更新聚合（仅统计型字段：已用额度、请求计数；不影响额度扣减正确性） | `true` |
| `BATCH_UPDATE_INTERVAL` | 批量更新间隔（秒） | `5` |

### 会话安全配置

确保集群中所有节点使用相同的会话和加密密钥：

```yaml
environment:
  - SESSION_SECRET=your_unique_session_secret # 所有节点必须相同
  - CRYPTO_SECRET=your_unique_crypto_secret # 所有节点必须相同
```

## 监控与维护

### 健康检查

配置定期健康检查以监控节点状态：

```yaml
healthcheck:
  test:
    [
      'CMD-SHELL',
      "wget -q -O - http://localhost:3000/api/status | grep -o '\"success\":\\s*true' || exit 1",
    ]
  interval: 30s
  timeout: 10s
  retries: 3
```

### 日志管理

对于大规模集群，建议使用集中式日志管理系统，或为日志配置独立的 `LOG_SQL_DSN` 数据库。

## 扩容指南

1. **准备新服务器**：安装 Docker 和 Docker Compose
2. **配置从节点**：按照「步骤三：配置从节点」的说明配置新的从节点
3. **更新负载均衡器配置**：将新节点添加到负载均衡器配置中
4. **测试新节点**：确保新节点能正常工作并参与负载均衡

## 最佳实践

1. **定期备份数据库**：即使在集群环境中，也应定期备份共享数据库
2. **监控资源使用情况**：密切关注 CPU、内存和磁盘使用情况
3. **采用滚动更新策略**：更新时，先更新从节点，确认稳定后再更新主节点
4. **配置告警系统**：监控节点状态，在问题发生时及时通知管理员

## 故障排除

### 节点无法同步数据

- 检查 Redis 连接是否正常
- 确认 `SESSION_SECRET` 和 `CRYPTO_SECRET` 在所有节点上是否相同
- 验证数据库连接配置是否正确

### 负载不均衡

- 检查负载均衡器配置和权重设置
- 监控各节点的资源使用情况
- 可能需要调整节点权重或增加更多节点

### 会话丢失问题

- 确保所有节点使用相同的 `SESSION_SECRET`
- 验证 Redis 配置正确且可访问
- 检查负载均衡器的会话保持策略
### 控制台刷新后返回 HTTP 429

- 按 IP 计数的 Web 限流（`GLOBAL_WEB_RATE_LIMIT`，默认 180 秒内 60 次）只统计 SPA 页面请求；未匹配的路径（未注册的接口、发版后已删除的分块等）按相同额度分开计数；入口脚本、懒加载分块等前端构建产物不计入，且在 `GLOBAL_STATIC_RATE_LIMIT_ENABLE=true` 之前不受限制
- 若所有客户端都显示为同一 IP（例如负载均衡器地址），全体用户将共享同一份额度：请把负载均衡器 / CDN 加入 `TRUSTED_PROXIES`，以使用真实客户端 IP；日志中出现 `request from <address> carries the X-Forwarded-For header but the source address is not in TRUSTED_PROXIES` 即属于这种情况
- 配置了 `FRONTEND_BASE_URL` 的从节点只重定向非 API 请求，不执行 Web / 静态限流；限流由实际提供前端页面的实例执行
- 使用共享 Redis 时，限流计数保存在 Redis 并按 Redis 服务端时钟计算：各节点无论自身时区都计入同一个窗口，被拒的请求不延长窗口，一个窗口内没有放行的计数到期清除；滚动更新期间新旧版本各自计数，最长持续一个窗口

### 更新后旧标签页进入新页面报错

- 滚动更新期间新旧实例并存，更新前打开的控制台页在进入没打开过的页面时，可能向新实例请求已被删除的旧分块（`/static/*`）
- 服务端对不存在的构建产物返回不可缓存的 JSON 404（`Cache-Control: no-store`），不会把首页 HTML 当作脚本返回；前端据此在同一标签页内自动刷新一次拉取新版本，再次失败则停留在错误页，需手动刷新
