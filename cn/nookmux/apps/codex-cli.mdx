## 安装

macOS / Linux：

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

Windows（PowerShell）：

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

也可以用包管理器安装：`npm install -g @openai/codex` 或 `brew install --cask codex`。

```bash
# 验证安装
codex --version
```

Windows 可以原生运行（推荐 Windows 11），也可以在 WSL2 中使用；macOS / Linux 直接在终端运行即可。

## 接入 NookMux

NookMux 提供 OpenAI Responses 兼容接口。Codex CLI 通过用户级配置文件 `~/.codex/config.toml` 接入，下面两种方式任选其一。提供商相关的配置只在用户级文件中生效，项目级 `.codex/config.toml` 里的同名键会被忽略。

### 方式一：自定义模型提供商

```toml
# ~/.codex/config.toml
model = "gpt-5.6"
model_provider = "nookmux"

[model_providers.nookmux]
name = "NookMux"
base_url = "https://your-domain.com/v1"
env_key = "NOOKMUX_API_KEY"
wire_api = "responses"
requires_openai_auth = false
```

把 `model` 换成你在 NookMux 渠道中配置的模型。这种方式的密钥取自 `env_key` 指向的环境变量，不需要执行 `codex login`。

macOS / Linux：

```bash
export NOOKMUX_API_KEY=sk-your-nookmux-token
codex
```

Windows（PowerShell）：

```powershell
$env:NOOKMUX_API_KEY = "sk-your-nookmux-token"
codex
```

### 方式二：覆盖内置 OpenAI 提供商的地址

```toml
# ~/.codex/config.toml
model = "gpt-5.6"
openai_base_url = "https://your-domain.com/v1"
```

内置的 OpenAI 提供商从登录凭据里读取密钥，用 NookMux 令牌登录一次即可。先把令牌导出为环境变量，再通过标准输入交给 Codex，避免留在命令历史里：

macOS / Linux：

```bash
export OPENAI_API_KEY=sk-your-nookmux-token
printenv OPENAI_API_KEY | codex login --with-api-key
codex
```

Windows（PowerShell）：

```powershell
$env:OPENAI_API_KEY = "sk-your-nookmux-token"
$env:OPENAI_API_KEY | codex login --with-api-key
codex
```

### 在 NookMux 侧获得密钥

1. 在控制台「密钥」页面创建或选择令牌，复制完整密钥（以 API Key 前缀开头，默认 `sk-`）。
2. 确认渠道中已配置要使用的模型，且模型名与配置文件里的 `model` 一致。

## 开始使用

```bash
cd /path/to/your/project
codex
```

启动后用 `/status` 查看当前使用的提供商和模型，用 `/model` 切换模型。也可以输入 `/config`，在 **Sessions** → **Model providers** 里切换提供商，或选择 **Create a custom provider or gateway** 新建一个。

## 常见问题

### 401 / 无效令牌

- 确认使用的是以 API Key 前缀开头（默认 `sk-`）的完整 NookMux 令牌。
- 方式一：确认 `env_key` 指向的变量已在启动 Codex 的终端里导出。
- 方式二：重新执行 `codex login --with-api-key` 写入新的密钥。

### 配置没有生效

- `model_provider`、`openai_base_url`、`model` 等顶层键必须写在第一个 `[xxx]` 表之前，否则会被归到那个表下面。
- 自定义提供商的 ID 不能与内置的 `openai`、`ollama`、`lmstudio`、`amazon-bedrock`、`amazon-bedrock-runtime`、`gcp` 重名。
- 旧版本的 `OPENAI_BASE_URL` 环境变量已被移除，请改用 `openai_base_url` 配置键。
- 修改配置后重启 Codex。

### 提示 Model metadata not found

`Model metadata for ... not found. Defaulting to fallback metadata` 只是告警：Codex 的内置模型目录里没有这个模型名，请求仍会正常发给 NookMux。

### npm 权限错误

改用上面的独立安装脚本，或用 Homebrew 安装：`brew install --cask codex`。
