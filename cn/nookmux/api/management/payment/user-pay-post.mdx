---
title: 发起易支付
description: 创建易支付充值订单并获取发往网关收银台的已签名参数。
api: "POST /api/user/pay"
---

通过已配置的易支付网关发起在线充值。服务端计算所请求充值数量的应付金额，创建一条待支付的充值订单，并返回签名后的提交参数与网关 URL，客户端打开该 URL 即可展示收银台。订单随后由易支付回调（`GET /api/user/epay/notify`）完成入账。

需要**用户（User）**权限（任意已登录账号）。管理接口的鉴权方式参见[身份认证](/cn/nookmux/api/management/auth)。

<Note>
该接口受更严格的按 IP 限流（CriticalRateLimit，启用时）约束，超限返回 HTTP `429`。
</Note>

## 请求

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/user/pay' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1' \
  --header 'Content-Type: application/json' \
  --data '{
  "amount": 10,
  "payment_method": "alipay"
}'
```

</RequestExample>

### 请求体

<ParamField path="body.amount" type="integer" required>
充值数量。不得低于配置的最低充值数量。
</ParamField>

<ParamField path="body.payment_method" type="string" required>
支付渠道类型，需与 `GET /api/user/topup/info` 返回的 `pay_methods` 中某个 `type` 值一致，例如 `alipay` 或 `wxpay`。
</ParamField>

## 响应

<ResponseExample>

```json 200
{
  "success": true,
  "message": "充值成功",
  "data": {
    "pid": "1000",
    "type": "alipay",
    "out_trade_no": "USR1NOAb12cd1730000000",
    "notify_url": "https://your-nookmux-domain/api/user/epay/notify",
    "name": "TUC10",
    "money": "73.00",
    "device": "pc",
    "sign_type": "MD5",
    "return_url": "https://your-nookmux-domain/console/log",
    "sign": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
  },
  "url": "https://epay-gateway-example.com/submit.php"
}
```

</ResponseExample>

### 响应字段

<ResponseField name="success" type="boolean" required>
订单是否创建成功且支付参数已生成。
</ResponseField>

<ResponseField name="message" type="string" required>
本地化的状态消息；`success` 为 `false` 时为错误描述。具体文案随请求语言变化。
</ResponseField>

<ResponseField name="data" type="object" required>
所创建订单的易支付已签名提交参数。

<Expandable title="data 结构">
  <ParamField path="pid" type="string" required>
    易支付网关配置的商户 ID。
  </ParamField>
  <ParamField path="type" type="string" required>
    支付渠道，等于请求中的 `payment_method`。
  </ParamField>
  <ParamField path="out_trade_no" type="string" required>
    所创建充值订单的订单号，格式为 `USR{user_id}NO{6 位随机字符}{unix 时间戳}`。
  </ParamField>
  <ParamField path="notify_url" type="string" required>
    支付完成后网关回调的通知地址。
  </ParamField>
  <ParamField path="name" type="string" required>
    商品名，格式为 `TUC{amount}`。
  </ParamField>
  <ParamField path="money" type="string" required>
    应付金额，保留两位小数。
  </ParamField>
  <ParamField path="device" type="string" required>
    收银台设备类型；`pc`。
  </ParamField>
  <ParamField path="sign_type" type="string" required>
    签名算法；`MD5`。
  </ParamField>
  <ParamField path="return_url" type="string" required>
    支付完成后网关跳转用户的地址（控制台日志页）。
  </ParamField>
  <ParamField path="sign" type="string" required>
    排序参数串的 MD5 签名。
  </ParamField>
</Expandable>
</ResponseField>

<ResponseField name="url" type="string" required>
易支付网关上的提交地址（`{网关地址}/submit.php`）。将 `data` 参数提交到该地址即可打开收银台。
</ResponseField>

## 错误说明

| 条件 | 说明 |
| --- | --- |
| 无效的参数 | JSON 请求体缺失或格式错误 |
| 充值数量不能小于最低值 | `amount` 低于配置的最低充值数量 |
| 获取用户分组失败 | 调用者的充值分组加载失败 |
| 充值金额过低 | 计算出的应付金额低于最低可收金额（0.01） |
| 支付方式不存在 | `payment_method` 不在已配置的支付方式中 |
| 当前管理员未配置支付信息 | 服务端缺少易支付网关地址、商户 ID 或密钥 |
| 拉起支付失败 | 网关拒绝了下单请求 |
| 创建订单失败 | 充值订单落库失败；详见服务端日志 |
