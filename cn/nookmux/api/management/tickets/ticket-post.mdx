---
title: 创建工单
description: 创建一张工单，包含标题、类型与首条消息，创建后为待处理状态。
api: "POST /api/ticket/"
---

创建一张归属于当前用户的工单。工单初始为 `pending` 状态，提交的 `content` 会成为会话的首条消息。

需要登录（**User** 权限）。管理接口的鉴权方式参见[身份认证](/cn/nookmux/api/management/auth)。

## 请求

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/ticket/' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1' \
  --header 'Content-Type: application/json' \
  --data '{
  "title": "Billing question",
  "type": "question",
  "content": "I was charged twice for the same request."
}'
```

</RequestExample>

### 请求体

<ParamField path="body.title" type="string" required>
  工单标题。校验前会去除首尾空白；不能为空，最长 255 个字符。
</ParamField>

<ParamField path="body.type" type="string" required>
  工单类型：`bug`、`feature`、`question` 或 `other`。
</ParamField>

<ParamField path="body.content" type="string" required>
  工单首条消息。校验前会去除首尾空白；不能为空，最长 10000 个字符。
</ParamField>

## 响应

<ResponseExample>

```json 200
{
  "success": true,
  "message": "",
  "data": {
    "id": 4,
    "title": "Billing question",
    "type": "question",
    "status": "pending",
    "created_at": 1748086400,
    "updated_at": 1748086400,
    "closed_at": 0,
    "messages": [
      {
        "id": 8,
        "type": "message",
        "role": "user",
        "username": "alice",
        "content": "I was charged twice for the same request.",
        "time": 1748086400
      }
    ]
  }
}
```

</ResponseExample>

### 响应字段

<ResponseField name="success" type="boolean" required>
  工单是否创建成功。
</ResponseField>

<ResponseField name="message" type="string" required>
  `success` 为 `false` 时的错误描述；成功时为空字符串。
</ResponseField>

<ResponseField name="data" type="object" required>
  创建后的工单。初始为 `pending` 状态，`closed_at` 为 `0`，仅有一条由提交的 `content` 生成的消息；消息的 `role` 由创建者账号角色决定（管理员创建为 `admin`，否则为 `user`）。

  <Expandable title="工单详情结构">
    <ResponseField name="id" type="integer" required>
      工单 id。
    </ResponseField>
    <ResponseField name="title" type="string" required>
      工单标题。
    </ResponseField>
    <ResponseField name="type" type="string" required>
      工单类型：`bug`、`feature`、`question` 或 `other`。
    </ResponseField>
    <ResponseField name="status" type="string" required>
      工单状态：`pending`、`processing` 或 `completed`。
    </ResponseField>
    <ResponseField name="created_at" type="integer" required>
      创建时间的 Unix 时间戳（秒）。
    </ResponseField>
    <ResponseField name="updated_at" type="integer" required>
      最近一次更新时间的 Unix 时间戳（秒），新消息与状态变更都会刷新该值。
    </ResponseField>
    <ResponseField name="closed_at" type="integer" required>
      工单完成时间的 Unix 时间戳（秒）；未完成时为 `0`。
    </ResponseField>
    <ResponseField name="messages" type="array" required>
      消息时间线，按消息 id 升序排列。

      <Expandable title="消息结构">
        <ResponseField name="id" type="integer" required>
          消息条目 id。
        </ResponseField>
        <ResponseField name="type" type="string" required>
          条目类型：`message` 为会话消息，`status` 为状态变更记录。
        </ResponseField>
        <ResponseField name="role" type="string" required>
          发送者角色，由发送者账号角色推导：管理员为 `admin`，否则为 `user`。
        </ResponseField>
        <ResponseField name="username" type="string" required>
          产生该条目的账号名称。
        </ResponseField>
        <ResponseField name="content" type="string">
          条目文本；仅当 `type` 为 `message` 时存在。
        </ResponseField>
        <ResponseField name="value" type="string">
          状态变更的目标状态（`pending`、`processing` 或 `completed`）；仅当 `type` 为 `status` 时存在。
        </ResponseField>
        <ResponseField name="time" type="integer" required>
          条目产生时间的 Unix 时间戳（秒）。
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
  管理接口在业务失败时同样返回 HTTP `200`，必须以 `success` 字段判断结果。服务层失败（标题或内容为空/超长、工单类型未知、数据库错误等）均以本地化的数据库错误文案返回，具体原因仅记录在服务端日志中。
</Note>

## 错误说明

| 条件 | 说明 |
| --- | --- |
| 请求体格式不正确 | JSON 请求体缺失或格式错误 |
| 数据库错误，请稍后重试 | `title` 或 `content` 去除首尾空白后为空或超长、`type` 不是 `bug`、`feature`、`question`、`other` 之一，或工单落库失败，详见服务端日志 |
