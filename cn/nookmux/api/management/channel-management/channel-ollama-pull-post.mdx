---
title: 拉取 Ollama 模型
description: 让 Ollama 渠道的上游服务器以阻塞方式拉取模型。
api: "POST /api/channel/ollama/pull"
---

让渠道背后的 Ollama 服务器拉取（下载）模型。仅接受 Ollama（`4`）类型的渠道，其他类型会被拒绝。

拉取请求以 `stream: false` 发往渠道上游的 `/api/pull` 接口，因此 HTTP 请求会阻塞到 Ollama 服务端下载完成；大模型耗时较长，上游请求的超时时间为 30 分钟。上游调用走渠道配置的代理（settings 中的 `proxy`），多 Key 渠道使用第一个密钥。渠道设置了 `base_url` 时覆盖内置默认地址（`http://localhost:11434`）。需要下载进度请改用[流式拉取 Ollama 模型](/cn/nookmux/api/management/channel-management/channel-ollama-pull-stream-post)。

需要**管理员（Admin）**权限。管理接口的鉴权方式参见[身份认证](/cn/nookmux/api/management/auth)。

## 请求

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/channel/ollama/pull' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1' \
  --header 'Content-Type: application/json' \
  --data '{
  "channel_id": 1,
  "model_name": "llama3.1:8b"
}'
```

</RequestExample>

### 请求体

<ParamField path="body.channel_id" type="integer" required>
  要拉取模型的 Ollama 渠道 ID。
</ParamField>

<ParamField path="body.model_name" type="string" required>
  要拉取的模型标签，需为 Ollama 服务端可识别的名称，例如 `llama3.1:8b`。
</ParamField>

## 响应

<ResponseExample>

```json 200
{
  "success": true,
  "message": "模型 llama3.1:8b 拉取成功"
}
```

</ResponseExample>

### 响应字段

<ResponseField name="success" type="boolean" required>
  模型是否拉取成功。
</ResponseField>

<ResponseField name="message" type="string" required>
  成功时为本地化的状态文案；`success` 为 `false` 时为错误描述。
</ResponseField>

<Note>
与多数管理接口不同，本接口失败时返回真实的 HTTP 状态码（`400`、`404`、`500`），而非一律 `200`；响应体仍为 `{ success, message }` 结构，成功时不返回 `data` 字段。请求会一直阻塞到下载完成或 30 分钟上游超时。
</Note>

## 错误说明

| 条件 | 说明 |
| --- | --- |
| 请求参数无效 | HTTP 400 —— JSON 请求体格式错误 |
| 渠道 ID 和模型名称不能为空 | HTTP 400 —— 缺少 `channel_id` 或 `model_name` |
| 渠道不存在 | HTTP 404 —— 给定的 `channel_id` 不存在 |
| 此操作仅支持 Ollama 渠道 | HTTP 400 —— 渠道类型不是 Ollama |
| 拉取模型失败 | HTTP 500 —— 上游拉取请求失败或返回非 200 状态码 |
