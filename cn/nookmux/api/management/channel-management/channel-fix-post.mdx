---
title: 修复渠道能力
description: 按当前渠道配置重建路由能力（abilities）表。
api: "POST /api/channel/fix"
---

重建路由能力（`abilities`）表：先清空该表，再按批为每个现有渠道重新生成能力记录。在导入或手工修改渠道数据后调用本接口，可让模型路由重新与渠道配置对齐。重建结束后重新加载内存中的渠道缓存。

需要**管理员（Admin）**权限。管理接口的鉴权方式参见[身份认证](/cn/nookmux/api/management/auth)。

## 请求

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/channel/fix' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1'
```

</RequestExample>

## 响应

<ResponseExample>

```json 200
{
  "success": true,
  "message": "",
  "data": {
    "success": 42,
    "fails": 0
  }
}
```

</ResponseExample>

### 响应字段

<ResponseField name="success" type="boolean" required>
  重建任务是否执行。
</ResponseField>

<ResponseField name="message" type="string" required>
  `success` 为 `false` 时的错误描述；成功时为空字符串。
</ResponseField>

<ResponseField name="data.success" type="integer" required>
  能力记录重建成功的渠道数量。
</ResponseField>

<ResponseField name="data.fails" type="integer" required>
  能力记录重建失败的渠道数量。
</ResponseField>

<Note>
  管理接口在业务失败时同样返回 HTTP `200`，必须以 `success` 字段判断结果。同一时刻只允许一个重建任务；并发触发的第二个请求会以数据库错误信息拒绝。
</Note>

## 错误说明

| 条件 | 说明 |
| --- | --- |
| 数据库错误 | 清空能力表、加载渠道失败，或已有重建任务在运行 |
