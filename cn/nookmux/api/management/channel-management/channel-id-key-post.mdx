---
title: 获取渠道密钥
description: 通过安全验证后查看渠道的完整上游密钥。
api: "POST /api/channel/{id}/key"
---

返回渠道的完整上游密钥。这是唯一会返回渠道密钥的渠道接口，因此受到多重保护：需要 Root 权限、受严格限流、禁止缓存，且调用方必须事先通过[安全验证](/cn/nookmux/api/management/security-verification/verify-post)。每次调用都会记入系统日志。

需要**超级管理员（Root）**权限。管理接口的鉴权方式参见[身份认证](/cn/nookmux/api/management/auth)。

<Note>
  本接口受严格限流和安全验证中间件保护：未通过安全验证的请求会在进入处理函数前被拒绝。响应带有 no-store 缓存指令。
</Note>

## 请求

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/api/channel/1/key' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1'
```

</RequestExample>

### 路径参数

<ParamField path="id" type="integer" required>
  要查看密钥的渠道 ID。
</ParamField>

## 响应

<ResponseExample>

```json 200
{
  "success": true,
  "message": "获取成功",
  "data": {
    "key": "sk-xxxxxxxxxxxxxxxxxxxx"
  }
}
```

</ResponseExample>

### 响应字段

<ResponseField name="success" type="boolean" required>
  是否成功返回密钥。
</ResponseField>

<ResponseField name="message" type="string" required>
  本地化的成功提示；`success` 为 `false` 时为错误描述。
</ResponseField>

<ResponseField name="data.key" type="string" required>
  渠道存储的完整上游密钥。多 Key 渠道返回以换行拼接的全部密钥。
</ResponseField>

<Note>
  管理接口在业务失败时同样返回 HTTP `200`，必须以 `success` 字段判断结果。
</Note>

## 错误说明

| 条件 | 说明 |
| --- | --- |
| 渠道 ID 格式错误 | 路径中的 `id` 不是整数 |
| 渠道不存在 | 给定 ID 的渠道不存在 |
| 获取渠道信息失败 | 渠道加载失败，详见服务端日志 |
