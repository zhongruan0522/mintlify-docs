---
title: 重置令牌密钥
description: 重新生成当前用户名下指定令牌的密钥；仅密钥变化，新完整密钥随响应返回。
api: "PUT /api/token/{id}/key"
---

重新生成当前用户名下单个令牌的密钥。仅 `key` 字段变化，令牌的名称、额度、模型限制等其他属性全部保持不变。同一令牌的并发重置由按令牌 ID 的互斥锁串行化，缓存在锁内同步切换，任意时刻最多只有一个有效密钥；旧密钥在重置完成后立即失效。新生成的完整密钥随响应返回，本次重置会记入审计日志。

需要登录（**User** 权限）。管理接口的鉴权方式参见[身份认证](/cn/nookmux/api/management/auth)。

<Note>
  本接口挂载了更严格的限流（CriticalRateLimit）。
</Note>

## 请求

<RequestExample>

```bash cURL
curl --request PUT \
  --url 'https://your-nookmux-domain/api/token/3/key' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1'
```

</RequestExample>

### 路径参数

<ParamField path="id" type="integer" required>
  令牌 id。
</ParamField>

## 响应

<ResponseExample>

```json 200
{
  "success": true,
  "message": "",
  "data": {
    "key": "sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
  }
}
```

</ResponseExample>

### 响应字段

<ResponseField name="success" type="boolean" required>
  密钥是否重置成功。
</ResponseField>

<ResponseField name="message" type="string" required>
  `success` 为 `false` 时的错误描述；成功时为空字符串。
</ResponseField>

<ResponseField name="data.key" type="string" required>
  新生成的令牌完整密钥（站点密钥前缀，默认 `sk-`，加 48 位随机串）。旧密钥自此立即失效。
</ResponseField>

<Note>
管理接口在业务失败时同样返回 HTTP `200`，必须以 `success` 字段判断结果。
</Note>

## 错误说明

| 条件 | 说明 |
| --- | --- |
| 参数非法 | `id` 不是整数 |
| 数据库错误 | 当前用户名下不存在该 id 的令牌、新密钥生成失败或落库失败；详见服务端日志 |
