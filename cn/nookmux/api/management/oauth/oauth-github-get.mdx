GitHub OAuth 回调。NookMux 通过统一的 `GET /api/oauth/{provider}` 路由注册 GitHub，此处 `provider=github`；用户在 GitHub 完成授权后由浏览器重定向到本端点。端点根据调用方会话完成两种流程：

- 未登录：查找或创建与该 GitHub 身份关联的 NookMux 账号并登录（响应会设置登录会话 Cookie）。
- 同一浏览器会话中已登录：将该 GitHub 身份绑定到当前账号，返回 `action: "bind"`。

在把用户重定向到 GitHub 之前，前端必须先在同一会话中调用[生成 OAuth State](/cn/nookmux/api/management/oauth/oauth-state-get)，该调用返回的 `state` 必须经 GitHub 原样回传到本端点。

本端点为**公开（Public）**接口，无需访问令牌，但挂载了更严格的限流（CriticalRateLimit）。管理接口的鉴权方式参见[身份认证](/cn/nookmux/api/management/auth)。

## 请求

<RequestExample>

```bash cURL
curl --request GET \
  --url 'https://your-nookmux-domain/api/oauth/github?code=gh-oauth-code-xxxxxxxxxxxx&state=abc123def456'
```

</RequestExample>

### 路径参数

<ParamField path="provider" type="string" required>
  OAuth 提供商名称。GitHub 为 `github`。当前 NookMux 注册了两个提供商：`github` 与 `linuxdo`。
</ParamField>

### 查询参数

<ParamField path="state" type="string" required>
  由 `GET /api/oauth/state` 生成并保存在该会话中的 CSRF state。必须与会话 Cookie 中的值一致，否则返回 HTTP `403`。
</ParamField>

<ParamField path="code" type="string" required>
  GitHub 返回的授权码。服务端用它交换访问令牌并获取用户信息。
</ParamField>

<ParamField path="error" type="string">
  授权失败时 GitHub 传入的错误码。存在时端点直接返回 `success: false`，不再请求 GitHub。
</ParamField>

<ParamField path="error_description" type="string">
  GitHub 传入的可读错误描述。`error` 存在时原样回填到 `message` 字段。
</ParamField>

## 响应

<ResponseExample>

```json 200
{
  "success": true,
  "message": "",
  "data": {
    "id": 42,
    "username": "octocat_12345678",
    "display_name": "Octocat",
    "role": 1,
    "status": 1,
    "group": "default"
  }
}
```

</ResponseExample>

### 响应字段

<ResponseField name="success" type="boolean" required>
  登录或绑定是否成功。
</ResponseField>

<ResponseField name="message" type="string" required>
  `success` 为 `false` 时的错误描述；绑定流程成功时为 `绑定成功`。
</ResponseField>

<ResponseField name="data" type="object" required>
  内容随流程不同。

  <Expandable title="登录 data 结构">
    <ResponseField name="id" type="integer" required>
      登录账号的用户 ID。
    </ResponseField>
    <ResponseField name="username" type="string" required>
      登录用户名。新注册的 OAuth 用户由提供商用户名与提供商用户 ID 拼接生成。
    </ResponseField>
    <ResponseField name="display_name" type="string" required>
      账号显示名称。
    </ResponseField>
    <ResponseField name="role" type="integer" required>
      角色：`1` 普通用户，`10` 管理员，`100` 超级管理员。
    </ResponseField>
    <ResponseField name="status" type="integer" required>
      账号状态：`1` 启用。
    </ResponseField>
    <ResponseField name="group" type="string" required>
      账号所属用户分组。
    </ResponseField>
  </Expandable>

  <Expandable title="绑定 data 结构">
    <ResponseField name="action" type="string" required>
      绑定流程恒为 `bind`，表示该 GitHub 身份已附加到当前登录账号。
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
  该接口挂载了更严格的限流（CriticalRateLimit）。登录成功时响应同时会设置控制台各端点使用的会话 Cookie。与多数管理接口不同，本端点有两种失败场景使用非 200 状态码：提供商未知返回 HTTP `400`，`state` 缺失或不匹配返回 HTTP `403`。管理员需先配置并启用 GitHub OAuth（客户端 ID）本流程才可用。
</Note>

## 错误说明

| 条件 | 说明 |
| --- | --- |
| 未知的 OAuth 提供商 | `provider` 未注册；HTTP `400` |
| state 参数为空或不匹配 | `state` 缺失或与会话不一致；HTTP `403` |
| 管理员未开启通过 GitHub 登录以及注册 | GitHub OAuth 未配置或未启用 |
| 提供商错误 | GitHub 传入 `error`/`error_description`；`error_description` 原样回填到 `message` |
| 无法连接至 GitHub 服务器，请稍后重试 | 交换令牌或获取资料时无法连接 GitHub |
| GitHub 获取 Token 失败，请检查设置 | 授权码交换失败，例如授权码无效 |
| 获取用户信息失败 / GitHub 获取用户信息为空，请检查设置 | 获取 GitHub 用户资料失败 |
| 管理员关闭了新用户注册 | 没有匹配账号且自助注册已关闭 |
| 用户已注销 | 关联账号已不存在 |
| 用户已被封禁 | 关联账号未启用 |
| 该 GitHub 账户已被绑定 | 该 GitHub 身份已被其他用户绑定 |
| 数据库错误，请稍后重试 | 账号或绑定落库失败，详见服务端日志 |
