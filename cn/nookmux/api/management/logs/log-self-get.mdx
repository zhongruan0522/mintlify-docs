---
title: 获取我的日志
description: 分页列出当前用户自己的用量日志，支持过滤与隐私脱敏。
api: "GET /api/log/self"
---

分页列出当前用户产生的日志，按时间倒序返回。用户名维度强制取会话用户，且条目按普通用户视角脱敏：移除渠道名称、剥离 `admin_info` 详情，并按使用日志字段可见性配置清空详情弹窗独有字段。

需要登录用户（**User**）权限。管理接口的鉴权方式参见[身份认证](/cn/nookmux/api/management/auth)。

## 请求

<RequestExample>

```bash cURL
curl --request GET \
  --url 'https://your-nookmux-domain/api/log/self?p=1&page_size=10&type=2&model_name=gpt-4o' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1'
```

</RequestExample>

### 查询参数

<ParamField path="query.p" type="integer" default="1">
  页码。
</ParamField>

<ParamField path="query.page_size" type="integer" default="10">
  每页条数，上限 100。分页助手同时兼容旧别名 `ps` 与 `size`。
</ParamField>

<ParamField path="query.type" type="integer">
  日志类型：`1` 充值、`2` 消费、`3` 管理、`4` 系统、`5` 错误、`6` 退款。缺省或 `0` 匹配全部类型。
</ParamField>

<ParamField path="query.start_timestamp" type="integer">
  Unix 时间戳（秒）；只返回 `created_at` 大于等于该值的日志。`0`（默认）表示不限下界。
</ParamField>

<ParamField path="query.end_timestamp" type="integer">
  Unix 时间戳（秒）；只返回 `created_at` 小于等于该值的日志。`0`（默认）表示不限上界。
</ParamField>

<ParamField path="query.token_name" type="string">
  按令牌名称精确匹配。
</ParamField>

<ParamField path="query.model_name" type="string">
  模型名匹配模式；允许 `%` 通配符（最多两个、不得连续、去掉 `%` 后关键词至少 2 个字符），`_` 与 `!` 按字面匹配。不含 `%` 时按模型名精确匹配。
</ParamField>

<ParamField path="query.group" type="string">
  按请求使用的分组精确匹配。
</ParamField>

<ParamField path="query.request_id" type="string">
  按 NookMux 请求 id 精确匹配。仅当 `request_id` 详情字段对普通用户可见时可用，否则请求被拒绝。
</ParamField>

<ParamField path="query.upstream_request_id" type="string">
  按上游供应商请求 id 精确匹配。仅当 `upstream_request_id` 详情字段对普通用户可见时可用，否则请求被拒绝。
</ParamField>

<ParamField path="query.ip" type="string">
  按客户端 IP 子串匹配。仅当 IP 地址详情字段对普通用户可见时可用，否则请求被拒绝。
</ParamField>

<ParamField path="query.ua" type="string">
  按存储的 User-Agent 请求头子串匹配。仅当客户端请求头详情字段对普通用户可见时可用，否则请求被拒绝。
</ParamField>

<ParamField path="query.x_title" type="string">
  按存储的 X-Title 请求头子串匹配。仅当客户端请求头详情字段对普通用户可见时可用，否则请求被拒绝。
</ParamField>

<ParamField path="query.http_referer" type="string">
  按存储的 Referer 请求头子串匹配。仅当客户端请求头详情字段对普通用户可见时可用，否则请求被拒绝。
</ParamField>

<Note>
本接口没有 `channel` 与 `username` 过滤：`username` 恒为会话用户，普通用户按渠道过滤会被直接拒绝。这些限制用于封堵通过 `total`、`items` 或统计结果变化对隐藏字段做侧信道探测。
</Note>

## 错误说明

| 条件 | 说明 |
| --- | --- |
| 使用日志详情已禁用，不支持按详情字段过滤 | 普通用户侧使用日志详情总开关关闭时使用了详情独有字段过滤 |
| 无权使用此过滤条件: channel | 普通用户按渠道过滤始终被拒绝 |
| 无权使用此过滤条件: request_id | `request_id` 字段对普通用户隐藏时按其过滤 |
| 无权使用此过滤条件: upstream_request_id | `upstream_request_id` 字段对普通用户隐藏时按其过滤 |
| 无权使用此过滤条件: ip | IP 地址字段对普通用户隐藏时按其过滤 |
| 无权使用此过滤条件: ua / x_title / http_referer | 客户端请求头字段对普通用户隐藏时按其过滤 |
| 数据库错误，请稍后重试 | 查询或统计日志失败，详见服务端日志 |

<Note>
过滤条件被拒绝时的文案为服务端固定返回的中文字符串，不随调用者语言本地化。
</Note>
