---
title: 获取兑换码密钥
description: 按需查看兑换码的完整密钥；每次查看都会记录到操作日志。
api: "GET /api/redemption/{id}/key"
---

按需返回单个兑换码的完整密钥。兑换码密钥是可直接兑换的凭证：创建接口仅在响应中一次性返回生成的密钥，此后列表、详情与更新接口均不回传密钥，本接口是唯一能再次查看完整密钥的兑换码接口。每次调用都会记录到调用管理员的操作日志。

需要**管理员（Admin）**权限。管理接口的鉴权方式参见[身份认证](/cn/nookmux/api/management/auth)。

<Note>
  响应带有 no-store 缓存指令，浏览器与中间代理不会缓存返回的完整密钥。
</Note>

## 请求

<RequestExample>

```bash cURL
curl --request GET \
  --url 'https://your-nookmux-domain/api/redemption/42/key' \
  --header 'Authorization: Bearer {access_token}' \
  --header 'New-Api-User: 1'
```

</RequestExample>

### 路径参数

<ParamField path="id" type="integer" required>
  要查看密钥的兑换码 id。
</ParamField>

## 响应

<ResponseExample>

```json 200
{
  "success": true,
  "message": "",
  "data": {
    "key": "e3f0c9d1a4b26f7c8d90e1a2b3c4d5e6"
  }
}
```

</ResponseExample>

### 响应字段

<ResponseField name="success" type="boolean" required>
  是否成功返回密钥。
</ResponseField>

<ResponseField name="message" type="string" required>
  `success` 为 `false` 时的错误描述；成功时为空字符串。
</ResponseField>

<ResponseField name="data.key" type="string" required>
  兑换码完整密钥（32 位无连字符 UUID）。
</ResponseField>

<Note>
管理接口在业务失败时同样返回 HTTP `200`，必须以 `success` 字段判断结果。
</Note>

## 错误说明

| 条件 | 说明 |
| --- | --- |
| 参数非法 | `id` 不是整数 |
| 数据库错误 | 不存在该 id 的兑换码，或读取失败；详见服务端日志 |
