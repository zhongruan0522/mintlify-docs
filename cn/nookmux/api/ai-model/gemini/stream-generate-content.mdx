title: 流式生成内容
description: 以 SSE 流式返回 Gemini 原生格式的内容生成，URL 需带 alt=sse 查询参数。
api: "POST /v1beta/models/{model}:streamGenerateContent"
---

以流式（Server-Sent Events）方式生成内容，请求与响应结构与「生成内容」一致，兼容 Google Gemini API 的 `streamGenerateContent` 方法。适合逐段输出长文本、实时展示思维链等场景。

NookMux 根据 URL 路径 `{model}` 中的模型名称将请求分发到对应渠道，并把上游 SSE 事件逐块转发给客户端。调用时必须在 URL 上附加 `?alt=sse` 查询参数：网关以该参数判定流式，未携带时请求将按非流式 `generateContent` 处理。

## 请求

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://your-nookmux-domain/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse' \
  --header 'x-goog-api-key: $NOOKMUX_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "写一个 Python 函数，计算斐波那契数列第 n 项。" }
      ]
    }
  ],
  "generationConfig": {
    "temperature": 0.7,
    "maxOutputTokens": 1024
  }
}'
```

```python Python
from google import genai

client = genai.Client(
    api_key="$NOOKMUX_API_KEY",
    http_options={"base_url": "https://your-nookmux-domain"},
)

for chunk in client.models.generate_content_stream(
    model="gemini-2.5-flash",
    contents="写一个 Python 函数，计算斐波那契数列第 n 项。",
):
    print(chunk.text, end="")
```

</RequestExample>

### 认证

推荐使用 `x-goog-api-key` 请求头传递 NookMux API 令牌（令牌在控制台「令牌」页创建）；网关同时接受 `Authorization: Bearer <token>` 与 `?key=<token>` 查询参数两种兼容写法。

<ParamField path="header.x-goog-api-key" type="string" required>
  NookMux API 令牌，格式为 `x-goog-api-key: <token>`。
</ParamField>

### 路径参数

action 固定为 `streamGenerateContent`，并须配合 `?alt=sse` 查询参数。

<ParamField path="path.model" type="string" required>
  要调用的模型名称，如 `gemini-2.5-pro`、`gemini-2.5-flash`。取值为 NookMux 中已配置的模型，可通过「模型列表」接口获取可用模型。
</ParamField>

<Note>
  请求体由网关按 Gemini 原生 DTO 解析并重建后转发，仅上述字段会被透传至上游；`tools`、`speechConfig`、`imageConfig` 等字段能否透传还取决于控制台「模型 → 参数覆盖」的配置。大部分字段同时接受官方 REST 的 camelCase 与 snake_case 两种写法（如 `system_instruction`、`inline_data`、`mime_type`、`top_p`），转发时统一规范化为 camelCase。
</Note>

<Warning>
  Gemini 原生中继仅支持 5 个 action：`generateContent`、`streamGenerateContent`、`countTokens`、`embedContent`、`batchEmbedContents`。其他 action（如 `generateAnswer`、`createTunedModel`、`:predict` 直调、视频生成 Veo 的 `generateVideos`）不支持：客户端 URL 中写入的 action 后缀会被网关丢弃，请求按 `generateContent` 处理或直接校验失败。
</Warning>

## 响应

单个 SSE 事件块的 JSON 结构与「生成内容」的非流式响应同构。字段说明见[生成内容](/cn/nookmux/api/ai-model/gemini/generate-content)的响应字段。

## 流式响应

响应以 `text/event-stream` 返回，每个 `data:` 行为一个完整的 GenerateContentResponse JSON 块，`candidates[0].content.parts` 中的 `text` 为本次增量片段：

```json
data: {"candidates":[{"content":{"parts":[{"text":"斐波"}],"role":"model"},"index":0}],"usageMetadata":{"promptTokenCount":24,"candidatesTokenCount":1,"totalTokenCount":25}}

data: {"candidates":[{"content":{"parts":[{"text":"那契数列第 10 项是 55。"}],"role":"model"},"index":0}],"usageMetadata":{"promptTokenCount":24,"candidatesTokenCount":9,"totalTokenCount":33}}

data: {"candidates":[{"content":{"parts":[{"text":""}],"role":"model"},"finishReason":"STOP","index":0,"safetyRatings":[{"category":"HARM_CATEGORY_HARASSMENT","probability":"NEGLIGIBLE"},{"category":"HARM_CATEGORY_HATE_SPEECH","probability":"NEGLIGIBLE"}]}],"usageMetadata":{"promptTokenCount":24,"candidatesTokenCount":62,"totalTokenCount":86,"thoughtsTokenCount":0}}
```

<ResponseField name="candidates" type="object[]">
  候选回复列表，结构与非流式响应相同，但 `content.parts` 中只携带本次事件的增量片段。开启 `thinkingConfig.includeThoughts` 时，思维链摘要片段（`thought` 为 `true`）会先于正文片段推送。
</ResponseField>

<ResponseField name="usageMetadata" type="object">
  Token 使用统计。中间事件块中为累计值，最后一个事件块（携带 `finishReason`）为完整统计，NookMux 以此完成计费。
</ResponseField>

<Note>
  与 OpenAI 格式不同，Gemini 原生流式响应没有 `data: [DONE]` 结束标记，流在最后一个事件块后直接关闭；客户端应以 `finishReason` 或连接关闭作为结束信号。
</Note>

<Note>
  URL 未携带 `?alt=sse` 时，网关按非流式请求处理并转发至上游 `generateContent`，客户端将收到单个 JSON 响应而不是 SSE 流。
</Note>

## 错误码

| HTTP 状态码 | 说明 |
| --- | --- |
| 400 | 请求参数错误（如缺少 `contents`），或模型不支持所请求的能力 |
| 401 | 令牌无效、已禁用或已过期 |
| 403 | 令牌无权访问该模型，或额度不足 |
| 429 | 触发速率限制 |
| 500 | 上游渠道返回错误，`error.message` 中包含上游错误详情 |

错误响应统一为 `{"error": {"message": ..., "type": ...}}` 的 JSON 结构。
